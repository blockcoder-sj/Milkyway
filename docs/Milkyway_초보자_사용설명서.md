# Milkyway 개인 PC 페이퍼 트레이딩 사용설명서

대상: 처음 사용하는 Q-Lab 학회원. 기준: `compose.personal.yaml` 개인 설치 모드.

**내 PC에서 프로그램을 실행하고, 본인의 증권사 키를 화면에 입력한 뒤, 종목과 전략 규칙을 저장하면 됩니다. AI 키는 필요 없습니다.** 미국 주식 현재가를 증권사에서 주기적으로 조회하고, 매수·매도는 Milkyway의 가상 원장에만 기록합니다. 증권사로 실제 주문을 보내거나 실제 계좌 잔고를 변경하지 않습니다.

## 1. 먼저 알아둘 범위

| 항목 | 개인 설치 모드의 동작 |
|---|---|
| 지원 증권사 | 한국투자증권 KIS, 토스증권 Open API |
| 지원 시장 | 미국 주식. 한국 주식·선물·옵션 운용은 지원하지 않음 |
| 시세 | 본인 증권사 키로 REST 현재가 조회. 기본 15초 작업 주기, WebSocket 틱 스트림 아님 |
| 과거 일봉 | 전략에 지정한 종목을 Yahoo에서 자동 준비·갱신. 첫 다운로드에도 인터넷 필요 |
| 전략 | 종목 1~20개와 허용된 6종류 지표를 최대 5개 조합. 임의 Python 코드 실행 아님 |
| 가상 체결 | 미국 정규장, 최신 일봉과 필요한 모든 최신 시세가 있을 때 실행 |
| 저장 | Docker의 개인용 데이터 볼륨. 브라우저 종료·컨테이너 재시작으로 삭제되지 않음 |
| 백업 | 별도 Docker 백업 볼륨에 시작 시 및 6시간마다 생성. PC 밖으로 복사해야 디스크 장애에도 대비 가능 |
| 계정·한도 | PC당 자동 연결되는 로컬 계정 1개, 전략 30개, 페이퍼 계좌 5개, 활성 계좌 전체 합계 20종목, 저장 전략 전체 합계 100종목, 백테스트 UTC 날짜당 100개 (한국시간 오전 9시 기준) |
| 성과 해석 | 내가 고른 현재 종목에 대한 탐색용 실험. 상장폐지까지 포함한 무편향 PIT 성과 인증 아님 |

`실전투자 키`는 키를 발급받은 증권사 환경을 뜻합니다. 이 프로그램 안에서는 어떤 환경을 골라도 가상 체결만 합니다. 실제 이용 가능한 시세의 지연·조회 한도는 본인 API 계약과 시세 권한에 따릅니다. KIS의 최근 시세 시각은 프로그램이 REST 응답을 받은 시각이며 거래소 체결 시각을 증명하지 않습니다. Toss는 공급자 응답에 포함된 시각을 사용합니다. 인증 성공만으로 미국 주식 실시간 시세 권한까지 확인된 것은 아닙니다. 공급자 조회 한도에 맞춰 종목을 나누어 조회하므로 15초마다 모든 종목이 갱신되는 것은 아닙니다. KIS 모의투자 환경에서는 20종목 전체 갱신에 약 1~2분이 걸릴 수 있습니다.

수업용 `compose.local.yaml`은 합성 데이터로 설치와 백테스트를 연습하는 별도 모드입니다. **1주일 개인 페이퍼 운용에는 이 문서의 `compose.personal.yaml`을 사용하세요.**

## 2. 설치 준비

준비할 것은 인터넷이 연결된 PC, Docker Desktop, 저장소 접근 권한, 본인의 증권사 API 키입니다. Git은 ZIP 다운로드를 사용할 경우 없어도 됩니다. Python을 PC에 따로 설치하지 않아도 Docker 실행·진단·백업은 가능합니다. 뒤의 간편 복원 도구에는 PC의 Python 3가 필요합니다.

1. Windows는 [Docker Desktop Windows 설치 안내](https://docs.docker.com/desktop/setup/install/windows-install/)에 따라 설치합니다. WSL 2와 가상화 관련 요구사항을 확인하고 **Linux containers**를 사용하세요.
2. macOS는 [Docker Desktop Mac 설치 안내](https://docs.docker.com/desktop/setup/install/mac-install/)에서 Apple Silicon 또는 Intel 중 본인 기종에 맞는 파일을 받습니다.
3. 설치 후 **Docker Desktop을 직접 실행**하고 엔진이 준비될 때까지 기다립니다.
4. Windows는 PowerShell, macOS는 터미널을 열고 다음 두 명령을 각각 실행합니다.

```console
docker version
docker compose version
```

`docker version`의 Client뿐 아니라 Server 정보도 보여야 합니다. `Cannot connect to the Docker daemon`이면 Docker Desktop부터 실행하세요. 화면에 보이는 `$`, `PS C:\...>` 같은 터미널 표시 문자는 입력하지 않습니다.

## 3. GitHub에서 다운로드

[Milkyway 저장소](https://github.com/blockcoder-sj/Milkyway)에 접근합니다. 비공개 저장소에서 404가 나오면 배포 담당자에게 GitHub 초대를 받고 로그인한 계정이 맞는지 확인합니다.

**Git을 쓰는 방법**

```console
git clone --depth 1 --branch codex/ai-research-workflow https://github.com/blockcoder-sj/Milkyway.git
cd Milkyway
```

비공개 저장소는 GitHub 인증이 필요합니다. 인증이 낯설면 아래 ZIP 방식을 사용하세요. 증권사 키는 GitHub 로그인용 비밀번호나 토큰이 아닙니다.

**ZIP으로 받는 방법**

1. 브랜치를 `codex/ai-research-workflow`로 선택한 뒤 `Code` → `Download ZIP`을 선택합니다. [GitHub 공식 다운로드 안내](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives).
2. ZIP을 **압축 해제**합니다. ZIP 내부에서 실행하지 않습니다.
3. 터미널에서 압축 해제한 폴더로 이동합니다. 경로에 공백이 있으면 큰따옴표로 감쌉니다.

```console
cd "다운로드한 Milkyway 폴더의 실제 경로"
```

폴더 안에 `compose.personal.yaml`, `Dockerfile`, `cloud_app`이 있는지 확인합니다. 아래 모든 명령은 이 폴더에서 실행합니다.

## 4. 처음 실행하기

```console
docker compose -f compose.personal.yaml up -d --build
```

첫 실행은 이미지와 패키지를 내려받으므로 시간이 걸립니다. 명령이 완료되면 상태를 확인합니다.

```console
docker compose -f compose.personal.yaml ps
```

`app`, `paper-worker`, `backtest-worker`, `personal-data`, `market-data`, `market-details`, `backup`이 실행되어야 합니다. `app`의 `healthy`는 웹 서버와 DB가 준비되었다는 뜻이며, 증권사 인증이나 실제 체결 성공까지 뜻하지는 않습니다.

브라우저에서 **http://localhost:8080** 을 엽니다. 다른 PC에서는 접속할 수 없도록 본인 PC에만 바인딩되어 있습니다.

1. 가입·비밀번호 입력 없이 `전략` 화면이 자동으로 열립니다.
2. 처음 실행할 때는 `내 로컬 계정`을 자동 생성합니다. 이미 계정이 하나 있으면 그 계정의 전략·계좌·키·기록을 그대로 사용합니다.
3. 브라우저를 다시 열거나 새로고침해도 같은 로컬 계정으로 연결합니다. 계정이 여러 개이거나 비활성 상태이면 자동으로 선택하지 않고 오류를 표시합니다.

이 PC를 사용하는 사람은 비밀번호 없이 기록과 설정에 접근할 수 있습니다. 개인용 구성의 loopback 바인딩을 유지하고 공용 PC나 외부 공개 서버에서 사용하지 마세요.

상단 `시장`에서는 한국·미국 주요 지수와 환율, 선물·원자재, 섹터 지수를 봅니다.
증권사 연결 전에 사용할 수 있는 공개 참고 데이터이며 1분마다 갱신합니다.
주요 지수·환율 카드는 눌러 상세 차트를 봅니다. 섹터 카드는 등락 요약만 표시하며
클릭되지 않습니다. 기업 분석·재무 자료·관계도는 초보자용 배포본에서 제외했습니다.
기준 시각이 오래되거나 수집이 실패하면 지연 표시가 붙습니다.
`내 전략 종목 · 증권사 시세`가 실제 페이퍼 체결용 가격입니다.
[시장 화면 항목과 데이터 의미](MARKET_DASHBOARD.md)

`8080`을 다른 프로그램이 쓰고 있다면 프로젝트 폴더에 `.env` 파일을 만들고 아래 한 줄만 넣은 뒤 동일한 실행 명령을 다시 실행합니다. 이미 `.env`가 있다면 다른 설정을 지우지 말고 해당 항목만 추가·수정합니다.

```dotenv
MILKYWAY_PORT=18080
```

이때 주소는 `http://localhost:18080`입니다. 증권사 키를 `.env`에 적지 않습니다. 프로젝트 이름과 데이터 볼륨은 고정되므로 폴더를 다시 다운로드해도 동일 PC의 개인 운용 기록을 이어 사용합니다. 별개의 개인 설치를 동시에 실행하지 마세요.

## 5. 본인 증권사 API 연결

화면 위 `증권사 연결 설정`, 또는 오른쪽 프로필 → `설정`에서 연결합니다. 키는 이 PC의 서버로 전달되어 암호화해 저장됩니다. GitHub, 단체 채팅, 스크린샷, 발표자료에 키를 올리지 않습니다. 입력창은 연결 요청이나 창 닫기 뒤 비워집니다.

### 한국투자증권 KIS

1. [한국투자증권 개발자센터](https://apiportal.koreainvestment.com/)의 서비스 이용 안내에 따라 Open API를 신청하고 본인 `App Key`, `App Secret`을 발급받습니다.
2. Milkyway에서 `한국투자증권 KIS`를 선택합니다.
3. **발급받은 키와 같은 환경**을 선택합니다. 실전투자용으로 발급한 키는 `실전투자 키`, 모의투자용 키는 `모의투자 키`입니다. 이름 때문에 임의로 모의투자를 고르면 인증이 실패할 수 있습니다.
4. 두 키를 붙여 넣고 개인 이용 확인을 체크한 뒤 `인증 확인 후 저장`을 누릅니다.
5. `인증 확인됨`을 확인합니다. 이후 미국 장중에 종목의 최근 시세가 들어오는지도 확인합니다. 미국 주식 시세 권한·환경별 제한은 개발자센터에서 확인하세요.

### 토스증권

1. [토스증권 Open API 공식 안내](https://corp.tossinvest.com/ko/open-api)에 따라 WTS에서 키를 발급하고 사용할 PC의 **공인 IP**를 허용 IP로 등록합니다.
2. Milkyway에서 `토스증권`을 고르고 `Client ID`, `Client Secret`을 입력합니다. 환경은 `실시간 시세 (내부 가상 체결)`입니다.
3. 개인 이용 확인을 체크하고 저장합니다.
4. 공유기 재연결, 다른 Wi-Fi, 핫스팟, VPN으로 공인 IP가 바뀌면 공급자 설정도 확인합니다.

두 공급자의 키를 섞어 넣지 마세요. 다른 공급자로 바꾸려면 새 공급자의 키 두 개를 다시 입력합니다. `연결 해제`는 시세 연결을 지우며, 전략·체결·잔고 기록은 보존합니다. 증권사 API 키가 없어도 개인 모드에서 가입·전략 작성·Yahoo 일봉 준비·탐색 백테스트까지 할 수 있습니다. 증권사 현재가 수신과 그 가격을 사용하는 페이퍼 체결에는 본인 키가 필요합니다. 별도 수업용 합성 데이터 모드로도 설치와 백테스트를 연습할 수 있습니다.

## 6. AI 없이 내 전략 만들기

`전략` → `내 규칙으로 전략 만들기`에서 입력합니다.

| 입력 | 의미와 예 |
|---|---|
| 전략 이름 | `나의 20일 모멘텀`처럼 나중에 구별할 이름 |
| 미국 주식 종목 코드 | `AAPL, MSFT, NVDA`처럼 쉼표로 구분. 최대 20개. 예시는 조작 연습용이며 종목 추천이 아님 |
| 선정 기준 | 모멘텀·평균회귀·저변동성·이동평균·거래량 모멘텀·RSI 중 선택 |
| 관찰 거래일 | 지표 계산 기간. 20이면 최근 20거래일 |
| 가중치 | 여러 기준의 결합 비중. 양수는 해당 기준 선호, 음수는 반대로 적용. 모두 0으로 둘 수 없음 |
| 최대 보유 종목 | 후보 중 점수가 높은 종목의 최대 개수. 입력한 종목 수 이하로 설정 |
| 리밸런싱 간격 | **달력일** 기준. 1이면 거래 가능한 날마다 점검. 휴일에는 체결하지 않음 |
| 손절 | 예: `-5`는 취득 평균가격 대비 5% 하락 기준. 시세 조회 사이의 가격 변동이나 갭으로 정확히 -5%에 체결되지 않을 수 있음 |
| 거래비용 | 편도 비용. 기본 `0.3%`를 가상 체결 때 반영 |
| 가격·거래량·이력 필터 | 조건 미달 종목은 매수 후보에서 제외. 조건이 너무 엄격하면 현금만 보유할 수 있음 |

RSI는 양수 가중치에서 RSI가 높은 종목을 선호합니다. 낮은 RSI를 활용한 평균회귀를 실험하려면 RSI 가중치를 음수로 설정합니다.

`전략 저장`을 누릅니다. `내 전략` 목록이 생기며, 별도 `personal-data` 프로세스가 해당 종목의 과거 일봉을 자동으로 준비합니다. 초기 다운로드는 네트워크나 공급자 상황에 따라 지연될 수 있습니다. 분할·배당 등 당일 기업행동을 확인할 데이터가 아직 없으면 개장 후에도 대기할 수 있습니다. 신호 계산에는 완료된 전일 일봉만 사용하며, 데이터가 준비되면 자동 재시도합니다. 화면의 과거 일봉 상태를 확인하세요.

전략은 저장 당시 규칙으로 고정됩니다. 규칙을 바꾸려면 새 이름으로 전략과 계좌를 만들어 결과를 비교하세요. 원래 계좌는 먼저 정지하면 두 전략이 동시에 운용되는 것을 피할 수 있습니다. `저장된 전략 규격 보기`에서 실제 저장된 설정을 확인할 수 있습니다.

## 7. 백테스트하기

1. `내 전략`에서 `백테스트`를 누릅니다.
2. 데이터 범위 안에서 시작일·종료일을 고릅니다. 한 작업의 구간은 최대 370일입니다. 시작일은 지표 계산을 위한 과거 이력이 충분히 있는 날로 선택합니다.
3. 개인 설치는 `탐색용` 모드입니다. 현재 선택한 종목을 과거에도 알고 있었다고 가정하므로 정식 PIT 성과로 표시하지 않습니다.
4. `작업 큐에 추가`를 누릅니다. 진행률이 표시되고, 완료되면 자산 곡선·수익률·낙폭·거래 수가 나타납니다.
5. 실패하면 실행 기록의 오류를 확인합니다. 최초 일봉 준비 중이었다면 상태가 준비된 뒤 다시 실행합니다. 같은 요청을 연달아 누르지 않습니다.

실행 기록은 50개씩 표시하며 `이전 기록`으로 넘깁니다. `전체 기록 JSON 저장`으로 모든 결과를 내려받을 수 있습니다. **개인 설치 모드는 백테스트를 30일 또는 50개 기준으로 자동 삭제하지 않습니다.** 디스크가 가득 차지 않도록 저장 공간을 확인하세요.

백테스트 성과가 실시간 페이퍼 성과와 같을 수는 없습니다. 백테스트의 일봉 체결 가정과 실제 관측 시점, 조회 지연, 갭, 선정된 종목의 생존편향이 다르기 때문입니다.

## 8. 페이퍼 계좌 시작과 기록 확인

1. 전략 목록에서 `페이퍼 계좌`를 누르고 계좌 이름을 정합니다.
2. 전략의 초기 가상자금으로 계좌가 생성됩니다. 실제 증권사 잔고와 무관합니다.
3. 계좌가 `운용 허용` 상태인지 확인합니다. 이는 실행 허용 상태이며, 당장 매수됐다는 뜻은 아닙니다.
4. 화면 위 운용 상태에서 증권사 인증, 프로세스 응답, 일봉, 시장 시간, 최근 시세를 확인합니다.
5. 계좌별 대기 사유를 확인합니다. 필요한 종목의 최신 시세가 모두 준비되면 가상 체결합니다. 후보가 없으면 현금을 유지합니다.
6. `체결·자산 기록 보기`에서 최근 체결과 자산 곡선을 확인합니다. `전체 체결 CSV 저장`, `전체 자산 CSV 저장`으로 전체 기록을 받습니다. 화면 표시 개수 제한 때문에 오래된 기록이 삭제되는 것은 아닙니다.

`정지`는 새 운용을 멈춥니다. 보유 종목을 자동 매도하거나 계좌 기록을 삭제하지 않습니다. `재개`하면 다음 적격 시점에 운용을 이어갑니다. 오류로 `검토 필요`가 된 계좌는 사유를 확인해야 합니다. 기록을 삭제해 경고를 숨기지 마세요.

이미 선택되어 계속 보유하는 종목의 수량은 매번 동일비중으로 다시 맞추지 않습니다. 제외된 종목을 매도하고 새로 들어온 종목을 매수하는 방식이므로, 매일 가격이 바뀌어도 매일 체결이 생기는 것은 아닙니다.

## 9. 1주일 운용 요령

**실행한 PC와 Docker가 계속 켜져 있어야 합니다.** 브라우저나 터미널 창은 닫아도 되지만, PC 종료·절전·노트북 덮개 닫기로 Docker가 멈추면 시세 수집과 가상 체결도 멈춥니다. 전원 어댑터를 연결하고 본인 OS의 전원 설정에서 운용 시간 동안 자동 절전을 끕니다.

매일 한 번 다음을 확인합니다.

- 계좌가 운용 허용 상태인지, 별도 검토 필요 사유가 없는지.
- 미국 장중 최신 시세 시각이 갱신되는지. 장외에는 마지막 시세 시각이 멈추는 것이 정상입니다.
- 과거 일봉이 최신 완료 세션까지 준비되어 있는지.
- 체결·자산 기록이 이어지는지. 같은 종목을 계속 보유하면 체결은 없어도 됩니다.
- 자동 백업이 최근 생성되었는지, Docker 저장 공간이 남아 있는지.

네트워크가 끊기면 오래된 가격으로 새 체결하지 않고 기다립니다. 연결이 복구되면 자동 재시도합니다. 중단 중 놓친 시세나 체결을 과거 시각으로 만들어 채우지는 않습니다. **PC·인터넷·증권사 장애를 포함해 1주일 무중단을 보장하는 시스템은 아닙니다.** 앱의 재시도·기록 보존 기능과 실제 운영 상태를 함께 확인해야 합니다.

## 10. 안전하게 종료·재시작·업데이트

실행 중인 기록을 보존하고 종료:

```console
docker compose -f compose.personal.yaml stop
```

이후 같은 설치 이어 실행:

```console
docker compose -f compose.personal.yaml up -d
```

프로세스가 멈췄을 때 재시작:

```console
docker compose -f compose.personal.yaml restart
```

코드를 업데이트할 때는 먼저 다음 절의 백업을 PC에 복사합니다. Git으로 받았다면 `git pull --ff-only`로 갱신하고 아래를 실행합니다. ZIP 설치는 새 소스를 받아 같은 개인 프로젝트를 재빌드합니다.

```console
docker compose -f compose.personal.yaml up -d --build
```

Docker Desktop의 볼륨 삭제, 공장 초기화, 전체 정리로 데이터 볼륨을 지우면 기록을 잃을 수 있습니다. 문제 해결을 위해 데이터 볼륨부터 삭제하지 마세요. 같은 PC에서 소스 폴더 이름만 바뀐 경우는 데이터 볼륨이 유지됩니다. 다른 PC로 옮길 때는 반드시 백업·복원합니다.

## 11. 백업·진단·복원

### 지금 백업하고 PC로 복사

자동 백업은 Docker 내부의 별도 백업 볼륨에 저장됩니다. 내부 백업만으로는 Docker 전체 초기화나 PC 디스크 고장을 막을 수 없으므로 정기적으로 PC 폴더와 별도 개인 저장장치에 복사합니다.

```console
docker compose -f compose.personal.yaml exec backup python -m cloud_app.local_ops backup
docker compose -f compose.personal.yaml cp backup:/app/backups ./backups
```

생성된 `milkyway-날짜-식별자.zip` 파일이 PC의 `backups` 폴더에 있는지 확인합니다. 반복 복사 시 같은 이름의 하위 폴더가 생겼는지도 확인하세요. 복원 때는 실제 ZIP 파일 경로를 사용합니다.

PC에 Python 3가 있으면 다음 간편 명령으로 생성·복사를 한 번에 할 수 있습니다. macOS에서 `python`이 없으면 `python3`, Windows에서 필요하면 `py`를 사용합니다.

```console
python deploy/local_tools.py backup
```

**백업에는 DB, 전략·원장, 시세 API 암호화를 해제할 로컬 키가 함께 들어 있습니다. ZIP 자체는 암호화 파일이 아닙니다.** 본인만 접근할 수 있는 저장소에 보관하고 GitHub·단체 채팅에 업로드하지 마세요. 손상 검사는 제공하지만 신뢰할 수 없는 사람이 준 ZIP을 복원하지 않습니다.

### 상태 진단

```console
docker compose -f compose.personal.yaml exec app python -m cloud_app.local_ops doctor
```

또는 PC Python 3로:

```console
python deploy/local_tools.py doctor
```

DB 무결성, 실행 프로세스, 데이터 상태 등을 확인합니다. 이 진단은 증권사에 실제 키를 보내 검증하는 명령이 아닙니다. 증권사 연결은 화면에서 확인합니다.

### 이전 버전에서 쓰던 비밀번호를 잊었을 때

현재 개인용 구성은 자동으로 연결하므로 비밀번호 재설정이 필요 없습니다. 이전 로그인 방식의 설치에서만, 가입할 때 입력한 이메일로 로컬 비밀번호를 재설정합니다. 아래 이메일은 본인 아이디로 바꿉니다.

```console
docker compose -f compose.personal.yaml exec app python -m cloud_app.local_ops reset-password my-email@example.com
```

새 비밀번호를 두 번 입력합니다. 입력 중 화면에 문자가 보이지 않는 것이 정상입니다. 비밀번호를 명령 뒤에 붙여 적지 않습니다. 기존 로그인은 만료되고 새 비밀번호로 다시 로그인하며, 전략·계좌·체결은 보존됩니다. 메일을 보내거나 증권사 비밀번호를 바꾸는 기능은 아닙니다.

### 백업으로 복원

복원은 선택한 백업 시점으로 돌아가는 작업입니다. 그 이후 생성한 기록은 현재 원장에서 사라지므로 백업 날짜를 먼저 확인합니다. 간편 도구는 실행 중인 프로세스를 정지하고 현재 데이터의 사전 백업을 만든 뒤 복원·재시작합니다. 복원에 실패하면 프로세스를 정지 상태로 남겨 혼합된 데이터로 운용하지 않도록 합니다.

```console
python deploy/local_tools.py restore "./backups/복원할-실제-파일명.zip"
```

예시의 파일명을 그대로 입력하지 말고 실제 ZIP 파일명으로 바꿉니다. 복원 후 로그인, 계좌 이름·잔고·최근 체결 시각, 증권사 연결을 확인하고 진단을 다시 실행합니다. 복원 직후 최신 일봉은 다시 갱신될 수 있습니다. 복원 오류가 발생하면 볼륨을 지우지 말고 원본 ZIP과 오류 문구를 보존하세요.

## 12. 문제 해결 표

| 증상 | 확인·해결 |
|---|---|
| GitHub 404 / clone 권한 없음 | 저장소 초대를 수락했는지, 로그인 계정이 맞는지 확인. 배포 담당자에게 접근 요청 |
| `docker` 명령 없음 | Docker Desktop 설치 후 새 터미널을 열기 |
| Docker daemon 연결 실패 | Docker Desktop 실행, 엔진 준비 대기. Windows는 WSL 2·Linux containers 상태 확인 |
| `no configuration file` / 파일 없음 | `compose.personal.yaml`이 있는 폴더에서 명령 실행, ZIP 압축 해제 여부 확인 |
| 빌드 다운로드 실패 | 인터넷·디스크 공간·Docker 저장 공간 확인 후 같은 명령 재시도. 임의로 버전이나 해시 잠금을 제거하지 않기 |
| `port is already allocated` | 4절처럼 `.env`의 `MILKYWAY_PORT` 변경 후 재실행. 해당 포트의 localhost 주소로 접속 |
| 브라우저 접속 실패 | `docker compose -f compose.personal.yaml ps` 확인. `localhost`와 설정한 포트 사용. 실제 오류는 아래 로그로 확인 |
| 자동 연결 불가 / 계정 제한 | 개인용 구성인지 확인. 계정이 여러 개이거나 비활성이면 자동 선택하지 않음. DB를 지우지 않기 |
| 세션 만료 | 새로고침하면 같은 로컬 계정으로 자동 연결. 기록은 유지됨 |
| 비밀번호 분실 | 11절 `reset-password`로 본인 로컬 계정 재설정. DB나 데이터 볼륨은 삭제하지 않기 |
| API 인증 실패 | 공급자·키 종류·실전/모의 환경 일치 확인, 앞뒤 공백 제거, 키 만료·폐기 여부 확인 |
| 토스 허용 IP 오류 | PC가 현재 사용하는 공인 IP를 공급자 허용 목록에 등록. VPN·다른 Wi-Fi·핫스팟 여부 확인 |
| 인증됨인데 시세 없음 | 미국 정규장인지, 활성 계좌가 있는지, 미국 시세 이용 권한이 있는지, 종목 코드가 지원되는지 확인 |
| 일봉 준비 중 / Yahoo 오류 | 인터넷 복구 후 자동 재시도 대기. 종목 오타·상장 시점·공급자 차단 여부 확인. 공급자 장애 동안 이전 기록은 보존 |
| 백테스트 실패 / 기간 부족 | 일봉 준비 완료 확인. 지표·최소 이력에 필요한 거래일을 확보하고 데이터 범위 안의 날짜 선택 |
| 백테스트가 계속 대기 | backtest-worker 실행 및 진단 확인. 실패한 작업의 오류를 먼저 읽고 다시 실행 |
| 페이퍼 계좌인데 매수 없음 | 시장 시간, 최신 일봉, 필요한 모든 종목의 최신 시세, 필터 통과 여부, 리밸런싱 간격을 차례로 확인 |
| `조건을 통과한 종목이 없습니다` | 전략의 최소 가격·거래량·이력 조건 확인. 종목이나 필터를 바꾼 새 전략으로 실험 |
| 시세 지연 / 네트워크 끊김 | 오래된 시세로 거래하지 않고 자동 대기. 연결 복구 후 최신 시세 시각 확인. 오류를 무시하는 강제 체결 옵션은 사용하지 않기 |
| Worker 응답 없음 | Docker 프로세스 상태와 로그 확인 후 `restart`, 진단 재실행. 브라우저 새로고침만으로 worker가 시작되지는 않음 |
| 기록이 없어 보임 | 같은 개인 모드·로그인·PC인지 확인. Docker 볼륨이 남았는지 확인. 최신 백업을 찾아 복원하기 전에 현재 볼륨부터 보존 |
| 오래된 실행/체결이 화면에 없음 | 백테스트 페이지 이동, 계좌 전체 CSV, 전체 JSON을 확인. 화면 표시 제한과 삭제를 구분 |
| 분할·기업행동 관련 검토 필요 | 자동으로 재개하지 말고 계좌 CSV와 사유를 보존하여 담당자에게 검토 요청. 지연된 기업행동이나 상장폐지는 임의 가격으로 정산하지 않음 |
| 디스크 부족 / 백업 실패 | 저장 공간 확보, 기존 백업을 외부 개인 저장장치로 복사. 데이터 볼륨 삭제로 해결하지 않기 |

상세 로그:

```console
docker compose -f compose.personal.yaml logs --tail=100 app paper-worker backtest-worker personal-data backup
```

도움을 요청할 때에는 발생 시각(한국시간), 수행한 동작, 화면의 오류, 실행 모드, 문제가 발생한 전략·계좌 이름을 전달합니다. 키·비밀번호·전체 백업은 보내지 않습니다. 로그나 스크린샷에도 자격증명이 없는지 확인한 뒤 필요한 부분만 공유하세요.

## 13. 수업 담당자 체크리스트

수업 전 저장소 초대, Docker 사전 설치, 본인 API 발급을 끝내도록 안내합니다. API 발급·시세 권한 승인은 수업 중 즉시 끝나지 않을 수 있습니다. 11월 4일 낮에는 설치·전략·백테스트·연결 인증을 실습하고, 미국 개장 뒤 각자 첫 현재가와 가상 체결을 확인하게 합니다.

개인 설치에서 각자 키를 자기 PC에 보관하는 방식은 중앙 서버가 학회원 키를 수집하는 부담을 줄입니다. 중앙 배포가 원천적으로 금지된 것은 아니지만 인증·키 분리·격리·시세 이용 권한을 별도로 갖춰야 합니다. **개인 설치용 Compose를 외부 주소로 공개하는 것으로 공동 서비스를 만들지 않습니다.** 기존 공개 서버의 배포·보안 검증 조건은 별도 문서에 그대로 적용됩니다.

키를 사용하지 않는 자동 검증의 실제 실행 결과와 미검증 범위는 저장소의 검증 보고서를 확인하세요. 실제 API 인증과 장중 최초 체결은 본인 키로 확인해야 합니다.

최종 점검: 한 명의 새 사용자가 저장소 다운로드부터 가입, 키 연결, 전략 저장, 백테스트, 계좌 생성, 첫 장중 시세, 체결 CSV, 백업 복사까지 따라 해 봅니다. 실제 API 인증과 실제 1주일 운영 여부는 합성 데이터·가속 테스트와 구분해 기록합니다.


### 개발·배포 담당자용 재현 명령

일반 학회원은 실행할 필요가 없습니다. 배포용 이미지를 만든 뒤 아래 하네스로 별도 설치의 HTTP 가입·전략·합성 백테스트·내보내기·재시작·강제 종료 복구·worker 중단 상태를 점검할 수 있습니다. 브라우저 조작 검증이나 증권사 키 인증을 대신하지 않습니다.

```console
python tests/run_personal_checks.py --image milkyway-personal:local
```

기본값은 외부 통신을 막은 격리 네트워크와 합성 일봉입니다. 이 모드의 HTTP 검사는 앱 컨테이너 내부에서 수행합니다. 호스트의 localhost 포트 연결 검사는 `--online-history` 모드 또는 실제 설치 점검으로 따로 확인합니다. 새로운 임시 프로젝트·볼륨만 사용하며, 종료 후 컨테이너는 내리고 증거용 볼륨은 남깁니다. 출력된 `report.json`에서 실행 결과와 생성된 볼륨 이름을 확인합니다. `--online-history`를 명시하면 과거 일봉에 한해 Yahoo 네트워크 조회를 허용합니다. 이 옵션도 증권사 키를 받지 않습니다.
