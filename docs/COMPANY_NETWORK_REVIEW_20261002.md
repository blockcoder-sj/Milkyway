## 공시에서 기업 이름과 관계 확인

무료 SEC 기업명/티커/CIK 목록의 정확한 전체 법인명을 토큰 trie로 탐색한다.
모호한 이름·여러 티커가 있는 미검토 발행사·자기 기업·문장 경계를 넘는 이름은
제외한다. 기존 검토된 브랜드 별칭을 보완하며 이름 유사도로 합치지 않는다.
Apple Hospitality REIT의 이름 안에 있는 Apple을 AAPL로 연결하지 않는다.

여러 관계가 있는 문장은 명시적인 구매·판매·협력·경쟁 절을 나눠 상대 기업을
찾는다. 경쟁 항목 안에 있는 공급 문장을 경쟁 관계로 바꾸지 않고, 보조 설명의
기업을 고객으로 연결하지 않는다. 가정·부정·종료 표현은 제외한다. 원래 발행사,
실제 공시 URL/anchor와 영문 증거를 보존한다. 인사 보상 문구는 제품으로 제외한다.

정확한 회사 이름도 관계의 존재를 입증하지 않는다. 역할을 명시한 문장만 대상이며
규칙이 놓치는 관계는 남을 수 있다. 수집 버전 4로 기존 제한된 큐에서 순차 갱신한다.
기존 수집 간격·SEC 간격/429 대기·응답/프로세스 제한을 완화하지 않았다.

## 업계 연결 탐색

`현재 기업 → 선택한 연결 기업 → 그 기업의 연결 기업`을 8개씩 탐색한다.
역할별 필터·페이지·다시 읽기와 기업 이름의 내부 상세 이동을 지원한다.
모든 선은 저장된 진술이다. 두 단계 경로를 첫 기업과 마지막 기업의 직접 거래로
만들지 않으며 같은 섹터·공급사·투자자를 공유한다는 이유로 관계를 만들지 않는다.

선택한 기업에만 확장 요청을 보낸다. 조회는 로컬 공개 SQLite만 사용하고 AI,
브로커, 사용자 원장을 호출하지 않는다. 첫 관계가 실제 저장된 사업 관계인지
다시 확인한다. 회사당 최대 400개 진술에서 사업 관계를 소유 관계보다 먼저
조회하고 여러 대상의 별칭은 한 번에 읽는다. 한 연결의 표시 근거는 10개로
제한하면서 전체 근거 수를 알린다. 하단 출처는 현재 보이는 경로만 추가한다.

## 직접 코드·보안 검토

변경 모듈을 직접 읽고 다음 경계를 확인했다. CodeRabbit은 사용하지 않았다.

- 새 GET의 기존 사용자 인증, 개인 로컬 전용 가드, canonical 기업 ID 검증,
  페이지 1–50·관계 종류 제한, 무관한 두 기업 요청 거부.
- SQL 값 매개변수와 최대 400개 placeholder; 동적 사용자 SQL·임의 URL 수집 없음.
- 기존 출처 검증·모델 재검증·백과 도메인/등급 거부·길이 제한 유지.
- 문단의 원래 근거와 역방향 진술 주체 유지; 사라진 직접 관계는 확장에서도 제거.
- DOM의 이름·요약·증거 escaping, 고정 내부 주소, HTTPS 외부 출처는 하단만 사용.
- 소유자·기업·화면·요청 epoch 변경 시 늦은 응답을 표시하지 않음.
- 사업 자료·프로세스·저장소·UI를 모듈로 분리. 새 의존성·AI 평가 하네스 없음.

이 검토는 단일 소유자 로컬 변경 범위다. 전체 저장소 deep scan이나 공용 OCI/KMS
배포 검증을 수행한 것은 아니다. AI 보강은 별도
[응답 검수](AI_RESPONSE_REVIEW_20261002.md)를 따른다. 새 유료 호출 승인은 대기 중이다.

보강했다. Microsoft 계약을 이미 완료된 납품·매출로 바꾸지 않고, Nutanix의
최종 계약/구현 예정 상태도 유지한다. 경쟁사 제품은 각각의 공식 서비스 자료로
정리했다. SEC 공개 DB의 CRWV/NBIS/NTNX 법인명과 Lambda의 기존 공식 도메인이
현재 `lambda.ai`로 연결되는 것도 확인했다. 광고성 성능 수치는 사용하지 않는다.

현재 검토 카탈로그 범위는 종목 프로필 78개·별도 기업 프로필 46개·관계 진술
179개다(기존 카탈로그 34개 + 확장 카탈로그 145개). 여러 주식 종류·사업 역할만
확인된 프로필이 포함되며 179개의 서로 다른 계약을 뜻하지 않는다.

- 판매 문장의 실제 수신자와 `with access to`의 제품을 구분한다. 회사의 제품·
  고객·공급사를 그 회사 자체로 잡지 않는다. 경쟁사의 자체 제품 경쟁은 유지한다.
- 과거 자동 SEC 진술만 보존된 원문에서 현재의 같은 역할·상대방 기준으로
  재검사한다. 사람이 검토한 진술·자회사 Exhibit와 다른 발행사의 근거는 유지한다.
- SQLite 삭제는 발행 주체·상대 기업·역할·설명·원문·출처가 모두 일치하는
  기록에만 적용한다. 모델 정리와 물리 관계 정리는 같은 트랜잭션이다.
- JSON 정리나 카탈로그 보강으로 내용이 바뀌면 타임스탬프가 같아도 DB를
  갱신한다. 반복 startup은 같은 결과를 유지한다.
- 순수 재검사 캐시는 2,048개로 제한한다. 새 수집 버전은 4이며 기존 수집
  간격·처리량·요청 제한을 유지한다. 유료 호출·개인 원장 변경은 없다.

실제 실행 공개 DB의 일관된 온라인 백업을 별도 사본에서 재검사했다.
프로필의 제외 후보 83개, 물리 관계 40,246 → 40,168개(78개 제외), 15.497초,
integrity ok·FK 오류 0. 프로필의 중복 원문과 물리 진술 ID의 중복 때문에 두 수는
같지 않다. 잘못된 ChronoScale의 NVIDIA 고객 진술이 제거됐음을 확인했다.
이 사본에는 추가 ChronoScale 카탈로그를 넣기 전이므로 배포 확인과 구분한다.

전체 회귀와 동시에 사본에서 30회씩 관계 조회한 중앙값/p95:
NVIDIA→Dell 30.12/107.58ms, Apple→TSMC 28.26/122.42ms,
TSMC→Amkor 28.91/111.99ms. 앞 표와 부하·자료 수가 다르므로 직접적인
성능 증감 비율로 비교하지 않는다. 사용자 공개 원본·거래 DB·볼륨은 복원하지 않았다.

추가 소스를 직접 검토했다. 제한된 원문/정규식, 기존 출처 모델 검증, SQL 값
