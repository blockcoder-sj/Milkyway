# 개인 로컬 구성 유지보수·검증 (2026-09-30)

## 범위

사용자가 확인한 운영 방식은 각 개인이 다운로드하여 자기 PC에서 실행하는 방식이다.
`compose.personal.yaml`과 SQLite를 기준으로 한다. Supabase·공개 서버 배포는 범위에
포함하지 않는다. 기존 runtime, .env 키, Docker 볼륨은 보존한다.

## 구조 변경

- `research_routes.py`: HTTP 주소, 인증·CSRF 의존성과 입력 검증 연결만 담당한다.
- `research_service.py`: 대화·승인·전략 버전·페이퍼 배치의 업무 흐름을 담당한다.
- `research_store.py`: 소유자 범위 조회와 응답 형태 변환을 담당한다.
- `research_ports.py`: 설정, 전략 생성, 계좌 생성 등 앱 기능을 명시적으로 주입한다.
  연구 모듈에서 `main.py`를 다시 불러오거나 그 전역 설정을 직접 읽지 않는다.
- `research_schemas.py`: 요청 입력 규격을 분리했다.
- 화면은 `research/api.js`(HTTP), `panel.js`(기본 구조), `view.js`(표시·이스케이프),
  `research.js`(상태·사용자 동작)로 분리했다. 늦게 도착한 조회가 새 사용자 동작을
  덮어쓰지 않도록 세대 번호로 구분한다. 승인 버튼 처리만 approve를 호출한다.
- 실험 결과가 다음 AI 요청에 중복 포함되던 것을 제거하여 불필요한 입력을 줄였다.

기존 main.py 전체와 클라우드 기능을 재작성한 것은 아니다. 새 연구 기능의 의존성과
책임을 분리하고, 이 경계를 자동 테스트로 검사한다.

## 확인한 항목

- 전체 회귀 테스트 **275개 통과**. Python 3.12, 임시 DB 및 합성 공급자 사용.
- 화면 코드 자동 테스트: 사용자·AI 문자열 이스케이프, 선택한 버전 보존,
  미리보기와 새로고침의 무과금·읽기 전용 처리, 명시적 승인 요청 내용.
- 실제 로컬 HTTP/별도 프로세스 검사 6개 항목 통과:
  1. 웹·paper·backtest·personal-data 프로세스 시작, 인증, 정적 파일 제공
  2. 잘못된 CSRF 거부, 미리보기에서 공급자 호출 없음
  3. 정상 재시작 후 승인 대기·로그인 유지, 중복 승인에도 합성 공급자 호출 1회
  4. 큐의 실제 백테스트 실행, 고정 버전의 페이퍼 계좌·기록 조회
  5. 웹 프로세스 강제 종료 후 연구·실험·계좌 데이터 보존
  6. 백업·복원 후 연구 대화·버전·실험·페이퍼 원장 DB 행 일치
- 잠긴 Python 의존성 **65개**를 pip-audit로 조회: 알려진 취약점 **0개**, 건너뛴 항목 **0개**.
- 직접 검토 범위: 소유자 검사, CSRF, 승인/취소/중복 요청, 요청 크기·호출 횟수 제한,
  실패 후 자동 재호출 방지, 키 제외, 출력 이스케이프, 데이터 고정과 계좌 버전 고정.
- 기존 테스트에서 현지 날짜와 UTC 날짜를 혼용하던 부분을 고정된 UTC 시각으로 수정했다.
  라우터 검사도 중첩 라우터를 포함하는 OpenAPI 경로 기준으로 변경했다.

## 재현

```bash
APP_ENV=development DATABASE_URL=sqlite:///:memory: python -m unittest discover -s tests -q
APP_ENV=development DATABASE_URL=sqlite:///:memory: python -m tests.run_native_personal_checks
```

Native 검사는 새로운 임시 폴더, 허용 목록 환경변수, loopback 전용 연결과 합성 공급자를
사용한다. 사용자 키·기존 DB를 읽거나 수정하지 않는다. 보고서와 로그는 출력된 임시 경로에
보존된다. 이는 Docker 이미지 검사와 실제 API 공급자 검사를 대체한다고 주장하지 않는다.

## 별도 확인이 필요한 항목

- 현재 세션에서 Docker 앱 제어와 Chrome 접근이 도구 권한 거부로 차단됐다.
  Docker Desktop의 실제 로컬 실행 및 이번 리팩터링 후 브라우저 화면 확인은 별도 항목이다.
- 실제 AI API 사용은 요청마다 사용자 승인 후 진행한다. 키 입력 자체는 승인으로 보지 않는다.
- 실제 증권사 인증·장중 시세·장기 페이퍼 운용은 합성 데이터로 입증할 수 없다.
- 저장소 전체 Codex Deep Security Scan은 AGENTS.md상 관리형 세션 조건이 있다.
  이번 직접 검토·의존성 감사·회귀 검사를 전체 보안 재감사 완료로 표시하지 않는다.
