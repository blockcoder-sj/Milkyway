# AI와 전략을 연구하고 페이퍼로 운용하기

## 개발 폴더와 키

이 PC에서는 `프로젝트/Milkyway` 하나를 사용합니다. 이전
`Milkyway-local-ready`는 같은 Git 저장소의 추가 작업 폴더였습니다.
최신 코드를 `Milkyway`로 통합했고 이전 수정본은 `프로젝트/output/backups/`에
보관했습니다. GitHub 저장소는 `blockcoder-sj/Milkyway` 하나입니다.

기존 `.env`를 열어 빈 키 칸만 채웁니다. 새로 설치했다면 `.env.example`을
`.env`로 복사합니다. 기존 `.env`를 덮어쓰지 마세요.

```dotenv
OPENAI_API_KEY=여기에_본인_API_키
OPENAI_MODEL=gpt-5.4-mini
OPENAI_REASONING_EFFORT=none
```

`.env`는 Git과 Docker 이미지에서 제외됩니다. Compose가 앱 프로세스에만
키를 전달하고 페이퍼·백테스트 worker에는 전달하지 않습니다.
이 PC의 파일은 소유자만 읽고 쓰는 권한으로 준비했습니다.

```bash
cd Milkyway
docker compose -f compose.personal.yaml up -d --build
```

키나 모델을 바꾼 뒤에도 같은 명령으로 앱을 다시 생성합니다.
개인용 설치는 웹 주소를 열면 가입·로그인 없이 같은 로컬 계정의 전략 화면으로 들어갑니다.
프로필 설정과 연구 화면의 **키 설정됨**은 파일 설정 확인입니다.
실제 공급자 인증이나 과금 가능한 연결 확인 요청은 자동으로 보내지 않습니다.

## 1. 가설을 말하고 승인하기

전략 화면에서 **새 연구 만들기**로 제목과 가설을 저장합니다.
대화에 사용할 미국 종목 코드와 규칙을 적고 **요청 미리보기 만들기**를 누릅니다.
이 단계에는 API 호출이 없습니다.

모델·추론 수준·최대 출력·전송 내용 전체를 확인한 다음
**이번 요청 1회 유료 호출 승인**을 누릅니다. 승인된 내용으로만 한 번 요청하며
실패·재시작·중복 클릭 때문에 자동 재호출하지 않습니다. 승인 유효 시간은 15분입니다.
호출 완료 여부가 불명확한 오류에도 재호출하지 않으므로, 새 요청 전에 기록을 확인합니다.
이미 전송된 요청은 공급자에서 처리되어 비용이 발생했을 수 있습니다.

최근 대화 최대 12회, 선택 전략, 최근 실험 3개와 페이퍼 기록이 다음 요청에 포함됩니다.
실험표도 최근 3개를 표시하며 전체 작업 기록은 아래 백테스트 실행 기록에서 확인합니다.
요청 크기를 넘으면 오래된 대화부터 제외하며 전체 기록은 로컬 DB에 남습니다.

## 2. 전략 버전 확인

AI가 질문하면 계속 대화하고, 전략을 제안하면 서버가 규격을 검증하여 새 버전으로
저장합니다. 기존 버전은 수정되지 않습니다. **대화 기준으로 선택**한 버전으로
수정 요청을 이어갈 수 있습니다. 규칙과 코드 미리보기를 먼저 확인하세요.

**Python 코드**는 검증된 규칙과 기존 실행 엔진을 사용하는 파일입니다.
임의의 AI 생성 Python을 서버에서 실행하는 구조는 아닙니다.
저장소 루트에 파일을 내려받고 같은 Python 의존성과 데이터 환경에서 실행합니다.
Docker 구성에서는 파일을 컨테이너로 복사한 후 그 환경의 데이터로 실행할 수 있습니다.
앱의 기간 비교 기능을 이용하면 별도 파일 실행이 필요 없습니다.

## 3. 후보를 같은 기간으로 비교

1~4개 버전을 체크하고 개발 시작일·검증 시작일·검증 종료일을 입력합니다.
각 구간은 최소 30일, 전체는 최대 370일입니다. 팩터와 필터에 필요한 준비 기간의
일봉도 시작일 이전에 있어야 합니다. 일봉 준비가 끝나지 않았다면 완료 후 다시 실행합니다.

후보의 초기자금과 편도 비용이 같아야 합니다. 데이터 세대를 고정해서 모든 후보가
같은 데이터로 실행됩니다. 검증 구간은 별도 초기자금으로 시작합니다.
개발 구간의 샤프 비율·수익률·최대 낙폭 중 선택한 기준으로 후보를 정렬하며,
검증 성과는 따로 표시합니다. 최대 4개 후보는 백테스트 8건을 사용합니다.

## 4. 결과를 보고 개선

“개발·검증 성과 차이를 설명해 줘”, “손절만 3%로 바꿔 줘”처럼 이어갑니다.
각 대화 요청마다 API 사용 승인이 필요합니다. 실험 계산 자체에는 AI 호출이 없습니다.
AI가 백테스트에 없는 수익이나 실험을 사실처럼 제시하면 실제 결과표를 기준으로 판단합니다.
검증 구간을 반복해서 보며 고르면 그 구간도 개발에 활용한 데이터가 됩니다.
최종 평가는 별도의 미사용 기간이나 이후 페이퍼 기록으로 진행합니다.

## 5. 버전을 정해서 페이퍼 시작

개발·검증 비교가 완료되고 검증 구간에 거래가 있는 버전을 선택해
**페이퍼 계좌 생성·운용 시작**을 누릅니다. 수익률이 양수여야 한다는 조건은 없습니다.
계좌는 해당 버전에 고정되며 이후 대화나 기준 버전 변경으로 전략이 바뀌지 않습니다.
계좌 카드에서 정지·재개하고 **체결 기록**에서 내역을 확인합니다.

본인 증권사 연결, 완료 일봉, 신선한 시세, 미국 정규장과 실행 프로세스가 준비되면
기존 코드가 가상 주문·현금·보유 수량을 처리합니다. 실제 증권사 주문은 전송하지 않습니다.
자동매매 중 AI를 호출하지 않습니다. PC·Docker가 꺼지면 실행도 멈춥니다.
시세는 REST 주기 조회이며 거래소 틱 스트림과 동일하지 않습니다.

## 모델과 지원 범위

기본값은 `gpt-5.4-mini` + `none`입니다. OpenAI 문서상 이 모델의 최저 추론 설정은
`none`입니다: https://developers.openai.com/api/docs/models/gpt-5.4-mini

모델은 가설 해석과 전략 작성에 영향을 줍니다. 저장된 전략의 백테스트·페이퍼 실행은
같은 결정적 엔진을 사용합니다. 비용을 줄인 설정으로 시작할 수 있지만 복잡한 가설의
해석 품질이나 전략 수익을 보장할 수는 없습니다. 상위 모델로 자동 변경하지 않습니다.

현재 지원: 토스에서 거래 가능한 미국 보통주·ADR·REIT 전체 자동 선별 또는 직접 고른 종목에서 일봉 모멘텀·평균회귀·저변동성·이동평균 괴리·
거래량 모멘텀·RSI 순위 조합, 가격/유동성/이력 필터, 매수 포지션,
달력일 리밸런싱, 비율 손절, 편도 비용. 일반적인 미국 시장 요청에는 고정 티커를 요구하지 않습니다. 전체 시장 목록·수정 일봉은 토스, 보유·선정 종목의 기업행사 확인은 Yahoo를 사용합니다. 현재 종목 목록을 소급하는 백테스트는 생존편향이 있는 탐색용입니다. 일봉 수집이 끝난 후 준비된 기간 안에서 비교합니다.

페이퍼 계좌 생성 시 운용 기간은 기본 7일입니다. 기간은 생성 시각부터 달력 7일이며 종료 후 추가 체결을 중지합니다. 계좌·전략 목록에서 삭제할 수 있고, 전략 삭제는 연결된 계좌를 먼저 정리해야 합니다. 직접 규칙 입력 폼은 제공하지 않습니다.

미지원: 임의 코드 실행, 분봉 신호, 뉴스·재무 조건, 섹터 순환,
공매도·레버리지·옵션·호가창 매매, 임의 지표 임계값 조합.
이런 요청은 정확히 지원되는 형태로 다시 정의하거나 실행 엔진을 확장해야 합니다.
증권사 키나 AI 키만 넣으면 모든 시장·섹터 데이터가 채워지는 것은 아닙니다.

## 검증

자동 테스트는 합성 AI 응답과 합성 가격을 사용합니다. 실제 GPT 응답 품질·키 권한·
증권사 시세 수신·장중 지속 운용은 별도 확인 사항입니다. 실제 AI API 테스트는
사용자 승인 후에만 진행합니다.

```bash
APP_ENV=development DATABASE_URL=sqlite:///:memory: python -m unittest discover -s tests -q
# 브라우저 확인용 서버: 실제 키와 기존 DB를 사용하지 않음
APP_ENV=development DATABASE_URL=sqlite:///:memory: python -m tests.serve_research_fixture
# 다른 터미널: Node 20+, Playwright 설치 필요. CHROME_PATH는 필요할 때 지정
node tests/run_research_browser.cjs
```

브라우저 스크립트는 합성 서버 표식을 확인한 뒤에만 승인 버튼을 누릅니다.
