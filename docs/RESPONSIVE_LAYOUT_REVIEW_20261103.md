# 창 크기 변경 대응 검토 · 2026-11-03

창 폭에 맞춰 패널·카드·입력란이 줄어들고 제목과 버튼이 재배치되도록 수정했다.
사용자가 요청한 현재 Chrome 앱에 반영했다. 실제 주문 기능과 자동 운용 상태는 바꾸지 않았다.

## 확인한 문제와 수정

1. 390px 전략 화면의 본문이 525px까지 늘어났다. 긴 영문 전략명이 grid의 최소
   너비를 밀어내 백테스트 지표·차트·설명이 잘렸다. 패널의 최소 너비를 해제하고
   긴 이름을 줄바꿈한다. 좁은 화면의 단일 열은 minmax(0, 1fr)을 사용한다.
2. 데스크톱에서는 접힌 직접 입력 편집기가 최소 530px 높이의 빈 열을 차지했다.
   개인 모드에서 편집기가 접혀 있으면 한 열로 배치하고 차트를 본문 폭으로 넓힌다.
   편집기를 펼치면 기존 화면 폭에 맞는 편집 배치로 돌아간다.
3. 입력란·선택란의 기본 최소 크기와 제목·상태 배지의 줄바꿈 조건을 정리했다.
   관계도 검색창과 선택란, 설정창의 저장 버튼도 좁은 화면에 맞춰 배치한다.
4. 기업·시장 상세의 다열 표는 최소 읽기 폭을 유지하고 표 내부에서 가로 스크롤한다.
   본문 전체를 가로로 늘리지 않는다. 글자 크기를 줄이거나 본문 넘침을 숨기지 않는다.

공통 보정은 static/responsive.css에 모았다. 기존 스타일 다음에 로드하며
index.html의 자산 버전을 갱신했다. 기존 차트·Canvas의 ResizeObserver를 유지했다.
새 JavaScript·의존성·제공사 호출 경로는 추가하지 않았다.

## 현재 Chrome에서 확인한 범위

시장, 전략, Energy 상세와 관계도, ExxonMobil 상세를 확인했다. 너비는
320·390·480·580·680·768·850·851·1024·1100·1101·1280·1440px이다.
직접 입력 편집기의 펼침·접힘, 설정창과 확대 차트의 400~900px 높이도 확인했다.
총 66개 상태에서 문서의 scrollWidth가 화면 너비를 넘지 않았다.

390px 전략 화면은 525px에서 390px로 본문 폭이 맞춰졌다. 접힌 편집기는
데스크톱에서 약 143px 높이로 줄었고 차트는 본문 폭을 사용한다.
확대 차트의 축·날짜와 관계도 Canvas가 변경한 표시 영역에 맞춰 다시 그려짐을 확인했다.
임시 viewport 설정은 해제했다. 기존 Chrome 탭 하나를 계속 사용한다.

이는 macOS Chrome의 실제 브라우저 검사다. 모바일 실기기·Safari·Windows와
전체 접근성 준수를 확인한 결과는 아니다. 다열 표의 가로 스크롤은 의도한 동작이다.

## 기능·성능·코드·보안 확인

- 최종 패키지 전체 Python 검사: 777개 중 756개 통과, 21개 건너뜀. 32.971초.
- 호스트 Node 기반 프런트엔드 검사: 23개 통과. 1.104초.
- 실제 HTTP 5회씩: 본문 200, 중앙값 1.664ms; 새 CSS 200, 중앙값 1.242ms.
  짧은 로컬 응답 표본이며 전체 화면 로딩 시간이나 부하 성능을 뜻하지 않는다.
- 변경 HTML/CSS를 직접 검토했고 git diff --check를 통과했다. 새 외부 자산·실행
  스크립트·인증 또는 주문 권한 변경이 없다. 전체 보안 재감사는 수행하지 않았다.
- 실행 이미지의 cloud_app/tests 코드·정적 자료 281개 SHA-256이 호스트와 일치했다.

## 반영과 데이터 보존

기존 검증 이미지 d14ee901을 고정 부모로 사용하고 index.html과 responsive.css만
추가한 로컬 이미지를 만들었다. 기존 의존성은 그대로다. 일반 Dockerfile 전체 빌드는
캐시가 없는 OS 설치 단계에서 외부망 차단 때문에 실패했으므로 새 의존성 빌드나
공급망 재검증 성공으로 기록하지 않는다.

최종 이미지:
sha256:0de12e7cc24142ea10680bc80db9b0d93e9c257dd69510b9dfa64edee7b19fbe

app만 교체했다. 다른 개인 서비스 3개의 ID·이미지·마운트와 다른 프로젝트의
실행 서비스 5개 ID를 보존했다. 개인 원장의 전략·백테스트·계좌·포지션·체결·평가·
하루 운용·연구 기록 10개 테이블의 행 수와 전체 행 SHA-256이 전후 일치했다.
페이퍼 계좌 1개, 가상 체결 3개, 평가 77개가 그대로다. 기존 볼륨을 복원하지 않았다.

live/startup은 200이다. ready는 503이며 paper/backtest 프로세스 미실행이 원인이다.
일봉·데이터 게이트·개인 데이터 프로세스는 정상이다. 새 AI 호출·증권사 주문·
CodeRabbit·하위 에이전트·Deep Scan·공개 배포는 수행하지 않았다.

증거는 runtime/verification-20261103/responsive/에 보관한다. 전후 화면,
layout-results.json, 검사 로그, HTTP 표본, 컨테이너·원장 비교와 이미지 SHA 목록이다.
화면과 개인 자료는 Git에 포함하지 않는다.
