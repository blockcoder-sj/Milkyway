# 반쪽 창의 백테스트 넘침 재현과 수정

사용자가 보고한 928px 창에서 결과 제목·지표·차트가 오른쪽 카드 밖으로 나왔다.
실제 Chrome 문서에는 responsive.css 연결이 없었다. 서버가 반환한 최신 HTML에는
같은 파일 연결이 있었고, 새로 불러오자 페이지와 카드 내부 넘침이 사라졌다.

진입 HTML을 재사용하던 캐시가 원인이다. `/` 응답에 `Cache-Control: no-store`를
추가했다. 버전이 지정된 정적 파일의 캐시는 유지한다. CSS를 다시 덮어쓰거나
넘치는 내용을 숨기지 않았다. 현재 Chrome에서 최신 화면을 다시 불러왔다.

## 검증

- 수정 전 새 회귀 검사는 진입 응답에 캐시 지시가 없어 실패했다. 수정 후에는
  이전 ETag를 보낸 경우에도 바뀐 HTML과 새 스타일 연결을 확인한다.
- 격리·망 차단 전체 검사 778개 중 757통과, 21건너뜀. 35.320초.
  호스트 프런트엔드 검사 23개 통과. 1.086초. 실제 제공사 호출은 없다.
- Chrome 320~1440px의 14개 너비에서 편집기 펼침·접힘 총 28개 상태를 검사했다.
  페이지 너비뿐 아니라 결과 카드 안의 제목·지표·설명·SVG 경계를 확인했다.
  28개 상태에서 넘침이 없다. 임시 화면 크기는 해제했다.
- 변경 경로를 직접 검토했고 인증·CSRF·CSP·주문·키 접근은 바꾸지 않았다.
  HTML은 재조회하고 API의 기존 no-store와 정적 파일 버전은 유지한다.
- 개인 원장 10개 테이블의 전체 행 해시가 전후 일치한다. 앱만 교체하고 다른
  컨테이너의 ID·이미지·마운트는 보존했다. 마운트 배열 순서는 정렬해 비교했다.
  오늘 밤 페이퍼 계좌와 paper/backtest/data 프로세스를 유지했다.

기존 앱 이미지를 부모로 main.py와 회귀 검사 파일만 반영했다. 최종 이미지:
`sha256:510901641f50078269db376b06e3c78de8d360e9ac7ce1a2641d56b0f75f66c3`.
HTTP 본문·CSS·live/startup/ready가 모두 200이며 진입 응답의 no-store를 확인했다.
실제 밤 체결, 전체 공급망 재빌드, 새로운 보안 전수 검증을 뜻하지 않는다.

로컬 증거는 `runtime/verification-20261103/backtest-containment/`에 보관한다.
화면·개인 원장·실행 증거는 Git에 포함하지 않는다.
