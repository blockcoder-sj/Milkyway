## DB 손상 발견과 복구

앱 갱신 시 기업 관계도 전용 `company-details/graph.sqlite3`에서 SQLite
malformed 오류가 발생했다. 거래 원장 `club.sqlite3`의 quick_check는 정상이었다.

- 손상 원본197,378,048바이트를 runtime의
  `company-details/quarantine-20261002T125625Z/graph.sqlite3`에 보존했다.
  SHA256: `8d9f82690d0489975f36a7e17676097e03bc4b98013810b6fa717c83c70f52d1`.
- 11:43 UTC 정상 백업의 관계도 파일만 추출, 백업 manifest의 크기·SHA256과
  전체 integrity_check=`ok`를 검증한 뒤 복구했다. 거래 원장·키·계좌는 복원하지 않았다.
  백업 그래프 SHA256:
  `4f06fdce8720cd160690af63e582006b7f88d695b7f18105382f8b276da358bc`.
- 기존 기업 JSON3,815개를 유지했다. 앱 초기화가 이 자료의 후속 변경과
  검토된 카탈로그를 관계도에 다시 반영한다. 정상 백업 이후 정보 전체의
  무손실 복원이라고 주장하지 않으며, 손상 원본은 추가 확인용으로 남겼다.
- 복구 후 거래 원장과 관계도 파일 모두 quick_check=`ok`를 확인했다.

## 파일 잠금 수정·보안 검토

`CompanyGraph.connection()`이 매 연결마다 SQLite 파일을 별도 os.open/close로
열고 닫는 경로를 발견했다. 이는 같은 프로세스의 다른 SQLite 연결이 보유한
POSIX 잠금을 해제할 수 있다. [SQLite 공식 설명 §2.2](https://sqlite.org/howtocorrupt.html#_posix_advisory_locks_canceled_by_a_separate_thread_doing_close_)과 일치한다.
실제 이번 손상의 단일 원인이라고 확정하지 않는다.

- 파일이 없는 경우에만 O_EXCL로 생성하며, 최초 생성은 프로세스 내부 잠금으로
  직렬화한다. 존재하는 DB에는 SQLite 외의 파일 open/close를 하지 않는다.
- 기존 파일의 종류를 링크를 따라가지 않고 확인하고, chmod도 no-follow로 실행한다.
- 별도 프로세스가 SQLite SHARED 잠금 영역을 획득하는 회귀 검사에서
  **수정 전 실패 / 수정 후 성공**을 실제 확인했다. 최초 생성 경합·링크 교체
  회귀 검사도 포함한다. 외부 링크 대상의 내용·권한이 보존되는지 검사했다.
- 독립 읽기 전용 검토자가 코드·회귀 검사를 검토했고, 제안한 링크 재검증과
  EACCES/EAGAIN 처리를 반영한 후 해당 범위에서 남은 High/Medium 없음으로 검토했다.
- 이 디렉터리는 개인 PC의 전용 데이터 영역이다. 같은 사용자 권한의 공격자가
  경로를 교체하는 환경에 대한 완전한 경쟁 조건 방어를 주장하지 않는다.
- UI는 설명·원문을 escape하고 출처 ID를 제한한다. 새 패키지, 외부 API URL 입력,
  임의 코드 실행, 키 노출·AI 자동 호출 경로를 추가하지 않았다. CodeRabbit 미사용.
- 전체 공개 배포 보안 검사/OCI/KMS 검증을 수행했다는 의미는 아니다.

## 자원 운영

정리 전8개 컨테이너 약1.05GiB → 불필요한 수집·백테스트3개 중지 후
5개 약536MiB. Chrome은 기존 Milkyway 탭1개를 재사용했다. 이 수치는 컨테이너
합계이며 Docker VM/앱과 다른 사용자 앱의 전체 메모리를 합한 값은 아니다.

수집·빌드·검사는 한 번에 하나씩 실행하고 임시 컨테이너는 --rm으로 제거한다.
company-data/market-details/backtest-worker는 필요할 때만 다시 실행한다.
페이퍼 운용·개인 데이터 준비 프로세스와 기존 runtime/backup 볼륨은 유지한다.

## 남은 범위

Energy의 전 기업·MLP·소형주 목록 확정, 회사별 경쟁·공급·판매·협력의 전수 조사,
시설/계약/수치 비교와 최신 공시 갱신은 계속 필요하다. 현재3개 기업조차 모든
항목을 완료한 것으로 계산하지 않는다. 공개되지 않은 정보나 무료 자료만으로
확정할 수 없는 수치는 만들지 않는다.
