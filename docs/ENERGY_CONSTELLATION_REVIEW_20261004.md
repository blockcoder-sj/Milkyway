# 에너지 3차원 관계도 검토

2026-10-04 사용자가 기업별 관계도와 에너지 섹터 전체를 우주 천체 모형으로
보고, 선택한 요소를 중심에 두며 가까운 관계를 우선 배치하도록 요청했다.
기존 Chrome의 Milkyway 탭에서 구현 결과를 확인했다.

## 구현과 자료 범위

- 시장 → Energy → **우주 관계도**에서 전체 지도를 연다. 기업 상세의 기업 관계도도
  같은 3차원 장면을 사용한다. 목록 페이지를 바꿔도 그래프를 8개로 자르지 않는다.
- 실제 앱의 최종 스냅샷은 **5,837개 요소·6,516개 연결**이다. 조사 기업 213개,
  직접 연결 기업 3,473개, 탐색 업종 19개, 제품·부문·산업 과정 1,645개,
  기업별·공통 영향 요인 486개, 연구 범위 노드 1개를 표시한다.
  공통 외부 요인은 8개이며 나머지는 기업 공시의 사업 요인이다.
- 공시로 편집한 213개 기업 관계와 이미 저장된 직접 이웃 및 이웃 사이의 관계를
  합친다. 전 세계 모든 회사·모든 변수의 완전한 원장이나 무제한 재귀 확장은 아니다.
  새 PC의 빈 회사 DB에서도 편집한 관계·사업 요소 3,140개/연결 3,781개가 나온다.
  현재 PC에서 추가 수집한 공개 원문까지 보려면 별도 자료 묶음도 전달한다.
- 회사는 정확한 종목·등록 ID·기존 별칭으로 식별한다. 동명이인·이름 유사성으로
  병합하지 않는다. 별도 사업 설명이 없는 이웃은 출처만 확보한 항목으로 표시한다.
- 실제 관계·사업 범위는 실선, 분류·산업 과정·영향 분석과 명시적 사업 비교는
  점선이다. 같은 두 회사의 실제 경쟁 진술과 편집한 비교는 별도 연결로 남긴다.
  대표 근거의 원문 링크·기준일·설명과 노드별 직접 이웃을 확인할 수 있다.

## 배치와 조작

실제 XYZ 좌표를 회전·투영하는 로컬 Canvas 장면이다. 외부 그래프 라이브러리,
CDN, WebGL 의존성을 추가하지 않았다. `korea-shipping-research`의 XYZ/Canvas
구현을 읽어 참고했으며 해당 프로젝트는 수정하지 않았다.

요소를 클릭하거나 검색 결과를 선택하면 중심이 바뀐다. 직접 연결을 먼저,
같은 단계에서는 공급·고객·소유·협력·사업 관계를 편집 분류보다 가까이 배치한다.
연결 단계가 먼 요소는 바깥으로 배치하며 중복 원문 수는 거리 점수를 올리지 않는다.
이 가중치는 탐색 규칙이며 거래액·지분율·실제 손익 영향·투자 중요도 점수가 아니다.
확인하지 못한 경제적 영향의 크기나 방향을 만들지 않았다.

XYZ의 천체 간 거리를 확보하고 투영된 화면의 점도 분리한다. 조밀한 화면은
작은 점으로 전체를 유지하고 이름표는 제한한다. 모든 등록 요소를 이름·종목으로
검색할 수 있다. 드래그 회전, Shift+드래그 이동, 확대·축소, 전체 맞춤,
2D 펼치기, 크게 보기, 키보드 선택·중심 이동을 지원한다.
두 포인터 확대는 이벤트로 구현했으며 실제 모바일 기기의 터치 검증은 하지 않았다.

기본 자동 회전은 꺼져 있다. 회전·재배치 중에만 계속 그리며 숨긴 화면·다른
페이지·백그라운드에서는 그리기를 멈춘다. 줄인 동작 설정을 존중하고
2D에서는 회전 버튼을 비활성화한다. 고밀도 장면은 이동 시 작업이 늘어나므로
모든 장치에서 부드러운 60fps를 보장하지 않는다.

## 실제 검증

- 최종 이미지에서 전체 **770개 / 23.444초 통과, Node 부재로 21개 skip**.
  호스트의 브라우저 모듈 **24개 / 1.088초 통과**. 실제 3D·2D 좌표,
  3,200개 밀집 요소의 겹침, 중심 선택, 유휴·가시성 중지, 출처 이스케이프,
  정확한 선 근거, 목록 페이징, 늦게 도착한 다른 사용자 응답을 검사했다.
- 회사 페이지의 400행 제한을 넘는 501개 역방향 원문도 섹터 지도에 모두 포함했다.
  빈 PC에서 관계 DB를 수집·변경하지 않는지, 캐시 복사·DB 변경 무효화,
  비개인/production 모드의 404와 자료 한도 초과의 413을 검사했다.
- 실제 공개 스냅샷 5,837개로 Energy/XOM/원유 가격 중심 × 3D/2D ×
  800×560/340×480의 **12개 조합**을 검사했다. 겹침 0·화면 밖 요소 0.
  Node 계산 최댓값: XYZ 배치 93.565ms, 투영 분리 99.196ms.
  이 수치는 브라우저 전체 프레임 속도나 실제 휴대폰 성능이 아니다.
- 제한된 512MiB/1CPU 오프라인 검증: 빈 PC 3,140개 첫 조립 165.722ms,
  편집 자료를 적재한 DB 첫 조립 155.552ms, 캐시 응답 중앙값 23.352ms,
  RSS 105,228KiB. 실제 앱 인증 HTTP는 5,837개 전체 JSON 수신 530.858ms.
- Chrome에서 전체 수 유지, XOM/DVN/원유 가격 중심 이동, 키보드 선택,
  2D 전환·EIA 근거, 기업 상세 이동을 확인했다. XOM 기업 지도는 46개 요소/
  48개 연결이며 목록 2페이지에서도 동일했다. SLB 선택 시 중심·정확한 관계
  근거 동기화를 확인했다. DevTools를 붙인 561px 폭에서도 도구 줄바꿈과
  천체 화면을 확인했다. 390px 기기 에뮬레이션 성공을 주장하지 않는다.
  마지막 로딩 전 조작·크기 0 화면의 방어 가드 두 개는 Node에서 검증했다.
  UI 검증 후 컴퓨터 제어 연결이 종료되어 해당 두 가드를 Chrome에서 추가 재현하지 않았다.
- Chrome 콘솔의 오류는 기존 favicon 404였고 MetaMask 경고도 별개였다.
  새 지도 모듈의 예외·CSP 완화·외부 코드 수신은 없었다.
- 실행 앱·호스트 소스/공개 자료/테스트 **279개 SHA 일치**.
  이미지 `sha256:8664a57b44a9ab4a8783d4ea9b84e3d87f32e144ff588d6afce62797d0f2780e`.
  `/health/live`·`/health/startup` 200, 미인증 지도 401, `/health/ready` 503.
  app만 교체했고 기존 마운트 동일, personal-data/market-data/backup 실행 유지.
  운용 worker·개인/백업 볼륨은 보존했다. 실제 브로커 장기 운용 증거는 아니다.

직접 소스 검토: 사용자 인증과 개인 모드 경계, 한도에서 조용한 누락 방지,
