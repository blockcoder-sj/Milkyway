# 기업 전체 구조·매출 비중·근거 검색 검토

2026-10-04, 개인 PC의 기존 Chrome 탭과 개인 앱에서 검증했습니다.
이 기록은 이전 선택 확대 검토 이후의 변경입니다.

## 수정한 동작

- 기업과 섹터 지도 모두 처음에는 전체 보기를 표시합니다.
  요소를 선택하면 선택한 요소와 주요 직접 연결 최대 8개를 확대합니다.
  상단 `전체 지도`와 화면 안 `전체 지도로 돌아가기`는 원래 기업·섹터를
  중심으로 전체 요소를 다시 표시합니다. `선택 주변`은 마지막 선택으로 돌아갑니다.
- 기업 지도에 현재 관계 필터의 기업 관계와 확보한 제품·서비스, 사업 부문,
  사업·실적 요인, 사업 분류 자료, 매출 구성 항목을 포함했습니다.
  목록의 페이지를 바꿔도 지도 전체 요소와 선택한 사업 요소의 설명은 유지됩니다.
  전체 보기는 현재 로드한 자료의 전체이지, 모든 미공개 관계를 뜻하지 않습니다.
- 원유·가스·정유·운송·시추·전력 등 인식한 사업 키워드의 요소를 같은 방향에
  모았습니다. 연결 단계와 탐색 우선순위도 거리 계산에 사용합니다.
  임베딩 의미 유사도나 정량 경제 영향도에 따른 군집은 아닙니다.
- `비중 기준`에서 제품·사업 부문·지역·매출 유형 등 확보한 구분을 선택할 수
  있습니다. 해당 구분의 최신 공시 매출 비중이 확인되면 가까운 연결의 우선순위와
  매출 천체 크기에 반영합니다. 선택 패널에는 금액·기간·통화·지표·출처를 표시합니다.
  비중은 같은 공시·기간·통화·지표의 항목 금액을 일치하는 분모로 나눈 값입니다.
  내부 거래 포함, 분모 불일치, 명시적 산출 제외는 비중을 만들지 않습니다.
  상위 합계와 그 포함 항목은 함께 표시되므로 더하지 않습니다.
  매출 구성비는 이익 비중·시장점유율·주가 민감도와 다릅니다.

## RAG의 현재 범위

에너지 지도의 `자료 근거 검색`은 지도에 포함된 출처 있는 설명, 확보한 공시 발췌,
관계 진술과 정량 매출 자료를 검색합니다. 검색 결과를 누르면 해당 요소와 정확한
관계 근거 패널을 엽니다. 공시 원문과 편집한 사업 설명이 함께 검색되므로 결과를
`근거 발췌`로 표시하고 원 출처를 제공합니다.

기존 공개 기업 SQLite DB에 재생성 가능한
[FTS5](https://www.sqlite.org/fts5.html) 인덱스를 추가했습니다. 원본 기업·관계·출처
테이블은 유지합니다. 자료의 지문이 바뀌었을 때만 파생 인덱스를 재구축합니다.
이번 실측 검색 대상은 12,769개 지도 근거 문서이며 검색 결과는 최대 12개입니다.

**RAG의 근거 검색 단계까지 연결한 상태입니다.** 벡터 임베딩 검색, LLM 생성 답변,
모든 공시 전문의 수집·청킹, 자연어 질문에서 경제 노출을 추론하는 기능은 완료하지
않았습니다. 키워드 검색 순위를 사업 비중으로 쓰지 않으며, 자료에 없는 요인의 영향
크기도 만들지 않습니다. 실제 AI 제공사 호출은 0회입니다. 새로운 무료 자료 전수
조사는 재개하지 않았습니다.

Chrome의 스크린샷과 DOM 상태로 실제 표시를 확인했습니다. 그리기 시간은 개별 프레임
표본이며 지속적인 60 FPS나 모든 기기의 성능을 보장하지 않습니다. 기존 유휴·화면 밖·
숨긴 탭의 애니메이션 중지 동작과 좁은 화면 geometry 검사는 유지했습니다.

전체 오프라인 검사 771개(21개 건너뜀)를 통과했습니다. 그 후 최종 설명·검색 발췌·
선택 설명 유지 변경은 관련 backend 5개(3.840s)와 host frontend 23개(0.569s)로
검증했습니다. backend 후속 검사는 네트워크 차단, 읽기 전용 이미지, 512 MiB·1 CPU,
임시 DB 경로를 사용했고 종료한 검증 컨테이너는 제거됐습니다.
검사 실행 중 누락된 환경 변수·쓰기 경로 설정을 수정한 기록도 증거 폴더에 보존합니다.

## 직접 코드·보안 검토와 보존 확인

- 새 검색 경로는 인증 의존성과 사용자별 60회/시간 제한을 사용합니다.
  인증 없는 실제 요청 401, 인증된 테스트 요청 200, 241자 쿼리 422,
  개인 모드 외부·production에서 404를 확인했습니다.
- 검색어는 제한한 단어 토큰을 따옴표로 감싼 AND 검색으로 전달하며 SQL은 매개변수화합니다.
  사용자 FTS 연산자 주입 검사를 통과했습니다. 결과 텍스트는 `textContent`, 설명과
  발췌는 기존 escape 함수를 사용합니다. 출처는 HTTPS·인증정보·출처 종류를 검증합니다.
- 기존 노드·관계 수 제한과 공시 payload의 개별 2 MiB / 합계 64 MiB 제한을 적용합니다.
  넘치는 자료는 413으로 실패하며 조용히 잘라서 전체라고 표시하지 않습니다.
- 기존 공개 원본 5개 테이블의 행 수와 같은 JSON 직렬화 기준 SHA-256이 모두 일치합니다.
  서로 다른 JSON 공백 설정에서 생긴 해시 차이는 동일 설정으로 재계산해 구분했습니다.
  SQLite `quick_check`는 `ok`입니다. FTS 테이블만 파생 자료로 추가했습니다.
- 개인 runtime·backup 및 다른 Docker 볼륨 목록과 마운트가 같습니다.
  personal-data·market-data·backup의 컨테이너 ID도 같습니다. 앱만 교체했습니다.
  paper-worker·backtest-worker는 시작하지 않았습니다.
- 실행 이미지 `sha256:7bac2b850247364ec4dbe209d4f89685a9b9ffaf947de5792b1a856a7c520d1d`의
  `cloud_app/`·`tests/` 280개 파일 SHA-256이 현재 소스와 일치합니다.
- `/health/live`, `/health/startup`은 200입니다. `/health/ready`는 기존 중지된
  운용 서비스·실시간 feed 조건 때문에 503이며 브로커 운용 준비 완료를 뜻하지 않습니다.
- 직접 소스를 검토했습니다. CodeRabbit, 하위 에이전트, 실제 AI 호출과 Deep Security
  Scan은 사용하지 않았습니다. 공개 배포·OCI/KMS 검증을 수행한 변경이 아닙니다.

로컬 증거: `runtime/verification-20261004/constellation-structure/`의 검사 로그,
실제 그래프·geometry 검사, runtime 측정, 원본 데이터·볼륨 보존 확인과 코드 manifest.
