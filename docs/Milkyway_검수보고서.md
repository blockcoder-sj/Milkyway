# Milkyway 개인 로컬 페이퍼 트레이딩 검증 보고서

검증일: 2026-09-26. 대상: `compose.personal.yaml` 단일 사용자 설치.

## 판정과 범위

개인용 실행 경로를 새로 완성했다. GitHub 사본에 별도 일봉 파일이나 AI 키를 넣지 않아도
실행·가입·전략 작성·일봉 준비·탐색 백테스트·페이퍼 계좌 생성이 가능하다.
증권사 시세는 본인의 KIS 또는 토스 키를 연결해야 한다. 매매 주문은 증권사로 전송하지 않는다.

실제 증권사 키가 없어 인증, 장중 시세 권한·지연, 실제 첫 시세 기반 가상 체결은 검증하지
않았다. 실제 일주일 연속 운용도 수행하지 않았다. 아래 가속·장애 테스트는 그 사실을
대신하지 않으며, **일주일 무중단이나 모든 외부 장애에 대한 보증은 아니다.**

지원 범위는 미국 주식, 제공된 6가지 팩터의 조합, 개인별 최대 20개 활성 종목이다.
임의 Python 전략 실행, 국내 주식 매매 엔진, 다른 증권사, WebSocket tick 스트림,
분할·배당 외 모든 기업행사의 완전 자동 정산은 지원 범위가 아니다.

| 데이터·기업행사 확인 전 잘못된 손절·수량 계산 | 종목별 당일 확인, 분할·배당 멱등 처리, 지연 이벤트 UTC 시각 기록, 불명확한 큰 가격 변화는 검토 대기 |
| 일정 수·기간 뒤 백테스트 자동 삭제 | 개인 모드에서는 자동 삭제하지 않음 |

## 실제 실행으로 확인한 내용

### 새 설치와 데이터 준비

- 독립 Docker 프로젝트·새 볼륨, `127.0.0.1:18082`에서 HTTP로 가입과 로그인 성공.
- AI 키 없이 AAPL/MSFT 전략 저장, 페이퍼 계좌 생성·일시정지·재개 성공.
- **실제 Yahoo 네트워크**에서 AAPL/MSFT 일봉 초기 다운로드 성공.
  마지막 완료 세션은 2026-09-25였다. 증권사 키는 사용하지 않았다.
- 준비된 실제 일봉으로 2026-03-02~2026-09-25 탐색 백테스트가 완료됐다.
  수익률 수치는 프로그램 통합 확인이며 투자 성과 주장이나 추천으로 사용하지 않는다.
- 키가 없는 상태는 `credentials_required`로 표시되고 증권사 시세를 만들어 내지 않았다.

### 기록 보존과 복구

독립 테스트 계좌에 **합성 가상 체결·자산 평가 기록**을 넣고 다음 작업 전후의
전략, 계좌 현금·보유 수량, 체결·자산 이력, 완료 백테스트를 전체 비교했다.

1. 모든 프로세스 정상 재시작: 일치.
2. 앱·페이퍼·백테스트 프로세스 `SIGKILL` 후 재시작: 일치.
3. `down` 후 새 컨테이너 생성: 일치. 데이터 볼륨은 삭제하지 않았다.
4. 실제 호스트 `local_tools.py` 백업 → PC의 권한 `0600` ZIP → 복원 → 재로그인: 일치.

복원은 현재 원장을 선택한 백업 시점으로 되돌린다. 사전 백업을 별도로 만들고,
손상 ZIP은 원장을 바꾸기 전에 거부한다. 복원이 중단되면 표시 파일로 앱 재시작을
차단한다. 계좌의 기업행사 검토 사유는 보존하고 이전 프로세스 heartbeat는 지운다.

### 자동 검증

- 전체 Python 회귀 테스트, 별도 PostgreSQL 역할·RLS·복원 검증을 실행한다.
- JavaScript 문법 검사와 Node VM 기반 화면 계약·입력 처리 검증을 실행한다.
- `tests/run_personal_checks.py`는 소스 디렉터리를 연결하지 않은 패키지 이미지로
  HTTP 가입·전략·백테스트·내보내기·재시작·강제 종료·worker 중단을 검증한다.
  기본 모드는 외부 네트워크를 차단하고 합성 일봉을 사용한다.
- `test_personal_paper.py`의 7일 가속 시나리오는 5개 거래일과 주말을 진행시키며
  시세 중단·반복 tick·연결 재생성·중복 체결 방지를 확인한다.
- 데이터 누락·손상·부분 다운로드·시간 초과·저장 실패·재시도, 분할/배당의
  지연 처리, 실패한 리밸런싱 rollback, 누적 기록 내보내기를 회귀 테스트로 검증한다.

로컬 패키지 전체 테스트는 **259개 실행, 실패 0개**였다(25.210초).
이후 클라우드 모드가 개인 종목 지정을 무시하지 않도록 거부하는 경계를 추가하고,
해당 회귀를 포함한 API·키 저장 테스트 **16개**를 다시 실행해 모두 통과했다.
이미지에 Node가 없어 건너뛴 JavaScript 동작 검증 1개는 호스트에서 별도로 실행해 통과했다.
호스트 프런트엔드 3개와 복구 8개 테스트도 통과했다.
별도 PostgreSQL 통합 검사 **8개**가 통과했다(5.487초). 이는 로컬 테스트 DB의
역할·RLS·HTTP·복구 동작 검증이며 실제 OCI 인프라 검증은 아니다.
패키지 HTTP 하네스는 위 설치·전략·내보내기·재시작·강제 종료·중단 상태의 7개 단계를 통과했다.
기본 외부망 차단 모드의 HTTP 요청은 컨테이너 내부에서 실제 서버에 전송했고,
앞의 별도 실제 일봉 통합 검증에서는 호스트의 localhost 포트로 요청했다.

## 반복 검수 방식

데이터·엔진·화면을 병렬 구현하고 서로 다른 에이전트가 상대 변경을 읽기 전용으로
검수했다. 발견한 호출 제한, 기업행사 최신성·시간대, 백업 일관성, 기록 절단,
상태 표시, 동시 저장 문제는 회귀 테스트를 추가한 뒤 다시 검수했다.
이는 해당 변경의 기능·복구 검수이며 저장소 전체 보안 인증이나 OCI 검증이 아니다.

## 아직 실제 환경에서 확인해야 하는 것

- 본인 키의 인증, KIS 실전/모의 환경 일치, Toss 허용 공인 IP.
- 각 계정의 미국 주식 시세 이용 권한과 공급자 지연. KIS 시각은 REST 응답 수신 시각이며
  거래소 체결 시각 증명이 아니다. Toss는 공급자 응답의 시각을 사용한다.
- 실제 장중 첫 시세 수신과 첫 가상 체결, 실제 일주일 연속 운영.
- Windows 실기기와 실제 브라우저 화면 조작. 현재 검증은 macOS Docker ARM64,
  HTTP, JavaScript 계약·동작 테스트에 기반한다.
- 정전·절전·인터넷 단절·증권사 장애 시 과거 실시간 체결을 복원할 수는 없다.
  돌아온 뒤 확인 가능한 신선한 데이터로 재개한다. 장중 운용에는 PC와 Docker가 켜져 있어야 한다.

일봉은 외부 공급자의 최선 노력 데이터다. 당일 기업행사 확인이 지연되면 체결을
대기하며, 상장폐지·합병·불명확한 가격 변화는 사용자가 검토해야 한다.
백업은 별도 개인 저장장치에도 복사해야 PC 디스크 고장에 대비할 수 있다.

## 배포에 대한 답

중앙 서버 배포 자체가 금지되거나 기술적으로 불가능한 것은 아니다. 다만 여러 사람의
키를 맡는 서버는 개인 PC와 다른 인증·키 격리·접근 통제·운영 책임이 필요하다.
이번 수업에는 소스를 공유하고 각자의 PC에 설치하는 구성이 맞다.
개인 모드를 외부에 노출하거나 공유 서버로 사용해서는 안 된다.
기존 공개 서비스의 OCI/Vault/IAM/Audit 및 보안 검증 gate는 그대로 미완료 상태다.

공급자 구현은 [한국투자 공식 예제](https://github.com/koreainvestment/open-trading-api),
[토스 공식 OpenAPI 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)를
확인했다. 실제 권한과 계약 조건은 본인 계정 기준으로 확인해야 한다.

## 재현 명령

```bash
docker build -t milkyway:verify .
docker run --rm -e APP_ENV=development milkyway:verify python -m unittest discover -s tests -v
python tests/run_personal_checks.py --image milkyway:verify
python tests/run_postgres_checks.py --image milkyway:verify
```

재현 하네스는 고유 이름의 테스트 프로젝트·볼륨을 사용한다. 실패 증거 보존을 위해
컨테이너만 내리고 테스트 볼륨은 남긴다. 기존 사용자 볼륨을 사용하거나 삭제하지 않는다.
