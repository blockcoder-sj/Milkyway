# 개인 페이퍼 운용 상태와 한 번 복구 검증

2026-11-03 개인 PC용 기능을 구현하고 현재 실행 앱에 반영했다. 인터넷 복귀 시 기존
활성 계좌는 자동 재시도한다. 앱·매매 프로세스 중지와 계좌 일시정지는 화면의
**자동매매 복구·재개**로 함께 점검한다. PC를 다시 켰거나 화면까지 닫았다면
**Milkyway 시작·복구** 실행 파일을 연다. 기존 계좌·잔고·보유량·체결 기록을 이어간다.

## 동작과 제한

- 프로그램 응답, 매매 프로세스, 증권사 시세, 계좌 허용 상태를 나누어 표시한다.
  최근 확인·프로세스 응답·API 점검·엔진 판단·가상 체결 시각을 함께 표시한다.
- 화면이 보이는 동안 5초마다 확인한다. 오래된 화면, 서버 연결 실패, 실행기 확인
  실패를 정상 자동매매로 표시하지 않는다. 저장된 heartbeat와 실제 컨테이너 상태를
  함께 사용하여 최근에 멈춘 프로세스도 구분한다.
- 복구는 고정된 개인 서비스 6개를 확인한다. 기존 컨테이너를 우선 시작하고 응답이
  끊긴 프로세스만 재시작한다. 웹 앱에 Docker 소켓을 마운트하지 않는다.
- 복구 시 본인 증권사 API를 실제 조회하여 허용 IP·인증·네트워크 문제를 확인한다.
  점검 가격은 체결용 시세 테이블과 가상 체결 원장에 저장하지 않는다.
- 종료된 하루 계좌·검토 필요 계좌·활성 종목 한도를 우회하지 않는다. 중복 클릭은
  실행기 작업 하나로 합치며 새 계좌 생성·가상자금 초기화·중단 시간 소급 체결은 없다.
- 토스 허용 IP나 API 권한·키 문제는 사용자가 수정해야 한다. 일주일 운용 계좌는
  생성 시 하루 전용 날짜를 비워야 한다. PC·인터넷이 꺼진 시간에는 로컬 운용도 멈춘다.

## 실제 확인

| 상황 | 결과 |
| --- | --- |
| paper-worker 실제 중지 | 화면이 프로세스 중지로 변경됐다. 버튼 한 번으로 기존 컨테이너와 같은 계좌를 복구했다. |
| app 실제 중지, 화면 유지 | 응답 미확인 표시 후 버튼이 별도 PC 실행기를 통해 앱을 시작했다. 계좌 상태를 다시 확인했다. |
| 오늘 계좌 일시정지 | 버튼 한 번으로 같은 계좌를 active로 재개했다. |
| 지난 10월 2일 하루 계좌 선택 | 종료 계좌 재개를 거절했다. 기록을 보존하고 오늘 계좌로 돌아왔다. |
| 시작 파일의 CLI 경로 | macOS Python 3.9.6에서 두 번 실행해 Docker·프로세스·계좌·실제 API 점검을 완료했다. |
| 네트워크·허용 IP·인증·요청 한도 실패 | 격리된 오류 주입 검사에서 고정 상태 코드로 표시하고, 회복 뒤 시세 수신으로 복귀했다. |
| 창 너비 320~1440px 14종 × 편집기 열림·닫힘 | 운용 상태와 백테스트 카드의 내부·페이지 가로 넘침이 없었다. 모바일·실제 928px 화면도 확인했다. |

기존 원장 10개 테이블의 행수와 전체행 SHA-256이 전후 동일하며 SQLite quick_check는
ok다. 전략 10개, 백테스트 작업 20개, 계좌 2개, 보유 3개, 체결 3개, 자산 기록 77개,
하루 일정 2개, 연구 대화 3개·발화 15개·버전 8개를 보존했다. 컨테이너 32개 중
app·paper-worker만 교체했으며 전체 마운트와 나머지 컨테이너 ID·이미지를 보존했다.

전체 격리 검사 804개 중 782개 통과·22개 건너뜀, 32.474초다. 건너뛴 항목은 격리
이미지의 Node 미설치에 따른 것이다. 호스트의 프런트엔드 24개와 실행기 13개는 모두
통과했다. 마지막 화면 변경은 호스트 검사로 다시 검증했다. Python 구문·JavaScript
구문·Mac 실행 파일 구문·diff 공백 검사도 통과했다.

로컬 HTTP 5회 표본 중앙값은 상태 API 4.299ms, 실행기 프로세스 조회 0.694ms다.
실행기는 조회를 3초 캐시하며 현재 메모리 표본은 약 15MiB다. live/startup/ready는
모두 200이다. 이 수치는 현재 PC의 짧은 표본이며 장시간·동시 사용자 부하 증명이 아니다.

## 직접 소스 검토와 현재 실행 상태

인증·CSRF·계좌 소유권·활성 종목 한도·기간 종료·시세 신선도 경로와 호출자를 직접
검토했다. 실행기는 127.0.0.1:19480에만 바인딩하고 정확한 Host·Origin·비공개 토큰을
함께 확인한다. 경로·명령 인자를 브라우저가 지정할 수 없다. 고정 서비스 외 명령,
볼륨 삭제·복원, 인증 토큰 리디렉션을 허용하지 않는다. 요청 크기·스레드·대기 시간을
제한했다. 오류 응답은 API 키나 원문 제공사 응답을 포함하지 않는다.

현재 Docker context는 로컬 Unix 소켓이다. 이 실행기는 본인이 신뢰하는 PC의 Docker
권한으로 실행한다. 공개 서버의 권한 격리나 OCI/KMS 검증을 대체하지 않는다.
Deep Scan·CodeRabbit·하위 agent·제공사 AI 호출·실주문은 수행하지 않았다.

현재 개인 서비스 6개와 실행기 PID 22744가 실행 중이다. 바탕화면의
`Milkyway 시작·복구.command`는 저장소의 `Milkyway-Start.command`를 가리킨다.
오늘 계좌 17bd2c846f8b46c1a5221a92bd8cb115는 active이며 개장 대기다.
최근 실제 토스 6종목 연결 점검은 성공했다. 오늘 밤 체결은 아직 확인하지 않았으며
당일 기업행사 자료 확인 등 기존 체결 조건을 유지한다. 하루 계좌 종료는 11월 4일
06:00 KST다. 종료된 하루 계좌를 이 버튼으로 다음 날 운용하지 않는다.

최종 app 이미지: `sha256:595902ea9850b2b6ee2fff16f14a431d9d0532c51387a17e7c8dfd6ad4f7ace4`.
실행 앱의 cloud_app 193개 파일 SHA-256이 작업 소스와 일치한다. paper-worker는
동일 백엔드의 b8b69b33 이미지이며 마지막 프런트엔드 표시 변경은 app에만 반영했다.
기존 의존성 이미지 위에 소스를 교체했으므로 의존성 전체 신규 설치 검증은 아니다.

실제 PC 전원 종료·Wi-Fi 차단·공유 Docker 엔진 종료·Windows 실기기는 시험하지
않았다. 앱/worker 중지 실험과 격리 오류 검사로 확인한 범위이며 일주일 연속 운용
증거는 아니다. 증거는 `runtime/verification-20261103/personal-recovery/`에 보관했다.
