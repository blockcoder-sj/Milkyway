# Energy 의미 검색·연관성 탐색·밀집 지도 검토

2026-10-04. 이전 구조·키워드 검색 검토의 후속이며 개인 PC용 작업입니다.

## 이번 범위

현재 확보한 기업·사업·관계·매출 근거를 대상으로 로컬 의미 검색과 의미 군집 배치,
출처를 따라 설명하는 연관성 패널을 연결했습니다. 기업·섹터 지도에서 중심과 주변
요소의 간격을 크게 줄였고, 3D 회전과 화면 이동을 모두 제공합니다.

- 직접 연결의 기본 반경 65 → 24, 2단계 210 → 55, 3단계 410 → 92.
  요소 수에 따른 제곱근 확장 대신 작은 로그 증가를 사용합니다.
  겹침을 허용하고, 선택 주변은 최소 화면 범위를 유지해 거리 축소를 자동 확대가
  상쇄하지 않습니다. 선택한 요소와 주요 직접 연결 최대 8개 표시 및 전체 복귀는 유지합니다.
- `드래그 동작`에서 `회전` 또는 `화면 이동`을 선택합니다. 이동 모드에서는 일반
  드래그로 화면을 옮깁니다. 우클릭·가운데 버튼·Shift 드래그도 이동합니다.
  두 손가락 제스처는 중심 이동과 핀치 확대를 함께 처리합니다. 가로 트랙패드 스크롤,
  Shift 휠, Alt 방향키로도 이동합니다. 전체 지도는 회전·이동·확대를 초기화합니다.
- `배치 기준`에서 의미 유사도 또는 연결·사업 키워드를 선택합니다.
  의미 군집은 실제 문서 벡터로 계산한 24개 군집과 3D 위치이며, 연결 단계·확인된
  매출 비중의 탐색 우선순위는 유지합니다. 3D 투영은 근사 표현입니다.
- `자료 검색`은 의미 검색과 단어 검색을 제공합니다. 기업 화면에서는 해당 기업의
  실제 지도에 있는 사업 요소와 직접 연결 기업·관계만 검색합니다. 주변 기업의 다른
  거래가 결과에 섞이지 않도록 제한했습니다.
- `연관성 분석`은 출처로 확인한 연결, 설명이 비슷한 요소, 기존 출처 있는 연결을
  최대 3단계 따라간 공통·외부 요인 경로, 선택 기준의 공시 매출 구성을 나누어 표시합니다.
  근거 발췌·출처·기업 상세를 열 수 있습니다. 유사도 추천으로 사실 관계를 추가하지 않습니다.

**의미 검색과 근거 기반 연관성 탐색은 구현했습니다.** 생성형 LLM의 자유 서술 답변,
모든 기업 공시 전문 수집, 비공개 거래·고객·투입 원가·주가 민감도의 추정은 이번 결과에
포함하지 않습니다. 관련 경로는 인과관계·영향 크기 증명이 아닙니다. 공시 매출 구성의
분모·기간·통화·제외·포함 관계 규칙은 이전과 같습니다. 무료 자료 추가 조사는 재개하지 않았습니다.

## 모델·자료 준비

[모델 저자의 multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small)을
로컬 CPU에서 실행합니다. revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`의
양자화 ONNX와 tokenizer 파일 2개를 고정하고, 매 실행 전에 크기와 SHA-256을 검증합니다.
벡터는 384차원, 질문·문서 접두사와 attention mask 평균·정규화를 적용합니다.
소스 오프셋으로 200토큰씩 32토큰 중첩 청킹하여 문서 끝을 보존합니다.
이미 앞 청크가 문서 끝을 포함하면 중복된 짧은 끝 조각을 만들지 않습니다.

이번 준비 결과는 원본 지도 7,435개 요소 / 8,114개 연결,
근거 문서 12,769개 / 청크 12,770개 / 고유 문서 벡터 12,486개입니다.
7,435개 모두 의미 위치를 갖습니다. 수록된 설명·확보한 발췌 범위이며 공시 전문 전수량이 아닙니다.
작업은 1 CPU·768 MiB 임시 컨테이너에서 순차 수행했고 중간 벡터를 재사용합니다.
수정 후 재준비에서 새 벡터 0개와 새 세대의 원자적 활성화를 확인했습니다.
이전 세대와 중단된 캐시는 보존하며, 현재 청크에 필요한 벡터만 제한된 SQL 묶음으로 읽어
누적된 과거 캐시가 준비 프로세스의 메모리에 모두 올라가지 않도록 했습니다.

의미 검색은 짧게 살아 있는 별도 추론 프로세스를 사용해 모델·tokenizer 메모리를 반환합니다.
[ONNX Runtime의 스레드 설정](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)을
사용해 CPU 스레드 수를 제한합니다. 질문은 외부로 전송하거나 DB에 저장하지 않습니다.
HTTP 요청은 모델 다운로드나 인덱스 생성을 실행하지 않습니다. 인덱스가 없거나 원본
지문이 바뀌면 의미 검색을 준비하도록 안내하며 단어 검색은 남겨 둡니다.

E5 유사도만으로 관련 없는 짧은 발췌가 상위에 나오는 표본이 있어 LNG·정유·CCS·우라늄 등
8개 한영 주제의 제목·발췌 신호로 재정렬합니다. 미인식 질문에는 임베딩 순위를 사용합니다.
이는 설명 검색 규칙이며 사업 비중이나 관계 증거로 쓰지 않습니다.

다른 PC에서는 기존 개인 데이터 복구를 먼저 검증한 뒤 다음과 같이 준비합니다.
모델은 Git에 넣지 않으며 약 136 MB의 공개 파일을 받습니다. 제공사 추론 호출은 없습니다.
기존 데이터·볼륨을 덮어쓰지 마세요.

```sh
docker compose -f compose.personal.yaml build app
docker compose -f compose.personal.yaml run --rm --no-deps \
  -e OPENBLAS_NUM_THREADS=1 -e OMP_NUM_THREADS=1 \
  app python -m deploy.prepare_constellation_semantics --download --batch-size 8
docker compose -f compose.personal.yaml up -d --no-deps --no-build app
```

의존성은 기존 base lock과 추가 `requirements-semantic.lock`의 wheel hash로 설치합니다.
Linux Python 3.11의 고정 lock 도구 환경에서
`python deploy/lock-dependencies.py --only requirements-semantic`으로 별도 재생성이 가능합니다.
