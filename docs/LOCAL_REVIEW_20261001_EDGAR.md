# 무료 공시·기업 관계도 검수 — 2026-10-01

대상은 개인 PC의 `compose.personal.yaml` 실행과 이번 변경이다. 기존 거래·연구
데이터 및 Docker 백업 볼륨을 보존했다. CodeRabbit은 사용하지 않았다.

## 구현과 실제 자료 확인

- 제공한 연락 이메일은 Git에서 제외한 `.env`에만 저장했다. SEC 요청 헤더와
  `company-data` 프로세스에만 사용하며 키·이메일 값을 기록하지 않는다.
- Wikidata가 실패해도 SEC 공식 종목 목록으로 CIK를 찾아 정확한 티커를 다시
  검증한다. 대용량 submissions와 공시 HTML, 연차보고서의 자회사 명세서 링크를
  지원한다. 최신 수정 공시가 짧은 표지라면 완전한 연차보고서를 우선한다.
- 규칙 추출과 공식 무료 발표로 공급·고객·협력·경쟁·자회사 자료를 보강한다.
  한 기업의 서로 다른 사업 역할과 원문은 각각 저장하며 화면에서 근거를 묶는다.
- 섹터 기업 순환 수집, 최대 200건 대기열, 수동 요청 우선과 20칸 예약,
  섹터당 후보 50개 검사·커서 저장, 정상 24시간/실패 1시간 갱신을 구현했다.
- HTTP 429는 해당 호스트만 Retry-After에 따라 대기한다. 실패 출처의 이전
  근거는 다른 출처의 새 자료와 함께 보존하고, 정상 갱신한 출처가 철회한 관계는
  다시 붙이지 않는다. 오류는 공급자 원문 대신 제한된 진단으로 표시한다.
- 시작하기 버튼과 기본 로컬 진입은 시장을 연다. 직접 전략·기업 주소도 유지한다.

| 실제 수집 대상 | 확인 결과 |
| --- | --- |
| NVIDIA 2026-02-25 연차 공시 | HTML 1,967,930바이트, 1,431문단, 본문 관계 진술 35건 |
| NVIDIA 자회사 명세서 | 원문 링크를 따라 3건 추가 |
| NVIDIA 최종 프로필 | 원래 근거 58건, 재무 항목 6개, 수집 오류 없음 |
| NVIDIA 화면의 사업 관계 | 중복 근거 묶음 후 공급 7·협력 4·경쟁 19·자회사 7 = 37개 |
| JPMorgan 2026-02-13 연차 공시 | HTML 12,927,439바이트, 6,647문단, 본문 규칙 관계 0건 |
| JPMorgan 추가 자료 | 자회사 18개, 재무 항목 5개, 공식 협력 기업 3개 |
| JPMorgan 공개 백과 | HTTP 429 대기 진단. SEC 자료는 독립 수집 성공 |

NVIDIA의 고객/모회사 0건은 해당 관계가 없다는 판정이 아니다. 익명 고객, 별칭
사전 밖의 기업, 규칙이 찾지 못한 진술은 추정하지 않는다. JPMorgan의 영업이익
US GAAP 항목이 없다고 다른 항목을 대신 넣지 않았다. 본문·명세서는 각각 최대
80건, 프로필은 기존 100건 상한을 유지한다. 전체 기업·분류가 완성된 상태는 아니다.

## 작동 검사

- 최종 이미지의 전체 Python 회귀: **423개, 63.865초, OK**, Node가 없는 이미지의
  프런트 검사 11개는 건너뜀. 실제 Node가 있는 호스트에서는 해당 기존 프런트
  그룹 **13개, 0.999초, OK**를 별도로 실행했다.
- 최종 순환 검사 보완을 포함한 공시·기업 집중 검사 **41개, OK**.
- 네트워크를 차단한 패키지 프로세스 통합 **8단계 모두 통과**: 실제 앱/worker
  시작, 인증·CSRF·기업 큐, 비상장 공통 ID·역방향 근거, 미리보기 무호출,
  재시작·승인 중복 차단, 백테스트·페이퍼 기록, 강제 종료 복구, 격리 백업/복원.
  공급자는 합성 자료이며 실제 AI 호출·사용자 계좌·사용자 데이터 복원은 없다.
- JS 세 파일 문법, Compose 설정과 `git diff --check` 통과.
- Chrome에서 시작하기 → `#market`, NVIDIA 관계도 → Micron 공통 ID 상세 → 이전
  화면, 공급사 원문 4건의 별도 표시, 분석 상태 및 분류 건수를 확인했다.
- 로컬 8개 서비스가 실행되고 앱 `/health/startup`이 `ready`를 반환했다.
  원래 runtime/backup 볼륨은 제거·복원하지 않았다. 공개 회사 DB 외래키 오류 0건.

SEC 경로 가드의 `.`/`..` 거부 보완을 포함한 최종 이미지에서 전체 검사와
8단계 프로세스 검사를 다시 통과했다. 검증한 로컬 이미지 ID는
`sha256:c1f3e28d43fcb7ea47821799b62cdbaa41c7b3b8eaf51f4dbc7a66fc44e9de00`이다.

## 성능

실제 공개 자료 DB의 온라인 백업 사본과 기술/금융 섹터 캐시를 격리 공간으로
복사했다. 사용자 거래 DB는 복사하지 않았다. 네트워크 연결을 차단하고 캐시
프로젝션을 30회씩 측정했다. Python HTTP 투영 함수의 시간이며 웹 전송·외부
공급자 지연이나 모든 기기의 화면 성능을 측정한 결과는 아니다.

| 캐시 조회 | 중앙값 | p95 | 연결 시도 |
| --- | --- | --- | --- |
| NVIDIA | 48.60ms | 76.07ms | 0 |
| JPMorgan | 51.19ms | 62.34ms | 0 |

같은 두 파일을 규칙으로 파싱한 3회 표본 중앙값은 NVIDIA 1.110초, JPMorgan
7.791초였고 최대는 각각 1.306/8.379초였다. 파싱은 별도 수집 프로세스에서 수행한다.
전체 회귀 검사를 동시에 실행한 앞선 부하 표본에서 캐시 p95는 최대 228.53ms였다.
출처의 네트워크 응답·전체 목록 채움 시간은 이 수치에 포함하지 않는다.

## 직접 코드·보안 검토

- 파싱, 수집/전송, 순환 일정, 실패 자료 보존, 저장 계약, UI의 책임을 모듈로
  나눴다. 기존 SQLite 공통 ID·출처·역방향 관계 저장 구조를 유지했다.
- 종목·CIK 일치, 같은 SEC 발행자의 명세서 경로, 고정 HTTPS 호스트, 리다이렉트·
  환경 프록시 거부, 응답 크기와 전체 프로세스 시간 제한을 검토하고 검사했다.
- 이메일 CRLF 거부, 백과 요청에 이메일 미전달, 기업 프로세스의 AI 키 부재,
  헤더/원격 오류 원문을 노출하지 않는 진단을 확인했다. `.env`는 Git 제외 대상이다.
- HTML은 실행하지 않는다. 원문·회사명·출처는 기존 HTML/SVG 이스케이프와
  URL 검증을 거쳐 표시하며 XSS 회귀 검사가 통과했다.
- 자회사 이름만으로 상장 종목을 합치지 않는다. 수집 입력에는 임의 URL을 넣을
  수 없다. 개인 API의 인증·CSRF·기존 회수 제한은 유지했다.
- 새로운 의존성, 유료 기업 자료, AI 임베딩·평가 하네스는 추가하지 않았다.
  이 검토는 변경 범위의 개인 로컬 검토다. 전체 심층 보안 감사와 OCI 공개 배포
  게이트를 통과했다고 주장하지 않는다.

## AI 및 남은 자료 범위

사용자가 승인한 새 AI 호출 5회는 **5/5 완료**, 3.7~5.4초였다.
세부 내용과 사용량은 [실제 AI 재검증 기록](AI_CHAT_REGRESSION_20261001.md)에 있다.
이 승인 범위는 모두 사용했으며 이후 추가 유료 호출은 없다.

한국 공시 확대에 필요한 무료 OpenDART 키를 요청했다. 환경 파일의 DART_API_KEY는
예약 항목이고 DART 수집기는 아직 구현·검증하지 않았다. 미국 SEC에는 별도 API
키가 필요하지 않는다. 대규모 기업 목록은 계속 순환 수집 중이며 공개 자료의
미공개 관계·지원하지 않는 문서와 임시 네트워크 장애는 남을 수 있다.

이 검수 문서와 구현은 `codex/ai-research-workflow`에서 함께 커밋한다.
