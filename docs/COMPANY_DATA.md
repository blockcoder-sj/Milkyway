# 개인 로컬 기업 정보

## 출처 원칙

Wikipedia/Wikidata/Wikimedia를 기업 지식 출처로 사용하지 않는다. 공급자 수신,
모델 검증, 기존 JSON 및 SQLite 이관에서 해당 설명·제품·관계·출처를 제거한다.
옛 기업 주소를 유지하기 위한 기존 식별 별칭은 지식 자료와 분리해 보존한다.
백과 전용 식별자만 있는 기업에 백과 수집을 다시 요청하지 않는다.
거래 DB와 사용자 백업 볼륨은 이 이관의 대상이 아니다.

| 출처 | 제공 항목 | 구분 |
| --- | --- | --- |
| 기업 공시·IR·제품 소개 | 핵심 사업·제품·수익 구조·사업 조건 | 기업·공시 원문 |
| SEC submissions/companyfacts | 정확한 종목·CIK, 공시, US GAAP·USD 연간 재무 6종 | 기업·공시 원문 |
| SEC 10-K/20-F·Exhibit 21 | 명시된 사업 관계·제품·위험 원문·자회사 명세서 | 기업·공시 원문 |
| 공식 공급망 목록·상대 기업 발표 | 제품·역할·국가·계약 범위가 확인된 관계 | 기업·공시 원문 |
| 공개 산업 조사·분석 자료 | 조사 기간·범위가 있는 경쟁·시장점유율 | 정보 제공사 |
| Npay/WiseReport | 한국 기업 개요·제공사 매출 구성 | 정보 제공사 |
| Yahoo/Npay 시세 캐시 | 시가총액·수집 기업 내 비중 | 정보 제공사 |

공식 공급사 목록, 계약 상대의 발표와 무료 산업 자료를 공시 본문과 함께 사용한다.
공개되지 않은 거래액·익명 고객·특정 제품의 공급사를 임의로 만들지 않는다.
지역 공급은 전 세계 거래로, 협력은 유상 판매로, 계획은 완료된 납품으로 바꾸지 않는다.
PepsiCo–Walmart의 직접·간접 매출 범위, Prologis의 부동산 임차 고객,
ASML의 DUV 경쟁 범위, 미국·캐나다 맥도날드 공급망을 따로 기록한다.

화면은 **기업 핵심 정리 → 사업·매출 구성 → 기업 관계도 → 제품·조건·재무 → 출처**
순서다. 본문에는 출처 번호만 표시하며 선택하면 하단 출처 모음이 펼쳐진다.
같은 문서의 여러 근거는 합쳐 표시하되 ‘근거 위치’에서 개별 공시 anchor를 보존한다.
긴 영문은 접힌 발췌이며 필요한 항목만 하단의 무료 Google 번역 링크로 읽을 수 있다.
해당 링크를 사용자가 눌렀을 때 선택한 공개 발췌문이 외부 번역 창에 전달된다.
앱에서 자동 번역·유료 AI 요청을 실행하지 않는다.

한국어 핵심 정리는 확인한 자료를 직접 요약한 읽기 자료다. 자동으로 모든 기업의
새 자료를 요약하거나 완벽하게 번역하는 AI 기능을 실행한 것은 아니다.
수치의 좋고 나쁨·가격 전망·투자 추천을 만들지 않는다. 제품 시장점유율, 매출 구성,
시총 비중은 서로 다른 개념이다. 출처 기준일과 수집 시각도 다르다.

## 연간 매출 구성

SEC 연차 공시의 Inline XBRL에서 표준 매출 지표와 연간 기간(300–400일),
해당 발행사의 CIK 및 화폐 단위를 확인한다. 제품·사업 부문·지역의 단일 축만
지원한다. 다차원/분기/미래/typed context와 비정상 값·상충하는 중복 수치는 제외한다.
표시 값은 공시의 scale을 적용한 원 통화 금액이다. 지리별 값은 공시의 지역 구분이며
최종 소비자 수요 지역으로 확대 해석하지 않는다.

비중 = 항목 매출 ÷ 동일 공시·지표·기간·통화의 차원 없는 연결 매출 × 100.
정확한 분모가 없거나 분자가 분모보다 크면 비중을 표시하지 않는다. 서로 다른
구분을 합산하지 않으며 제품/서비스 총구분도 개별 제품군과 별도 화면에 표시한다.
NVIDIA의 컴퓨팅+네트워킹 값이 데이터센터 값과 일치하는 경우에만 포함 관계를
표시한다. 전체 행 합계나 모든 회사의 중복 없는 구성을 임의로 만들지 않는다.
계산 방법·원래 지표/구성원 식별자를 접힌 설명에서 확인할 수 있다.

기존 수집 버전은 일괄 외부 호출 없이 한 시간 이후부터 기존 제한된 큐에서
순차 재처리한다. 지원되지 않는 형식은 빈 구성이며 공개 재무 수치를 대체하지 않는다.

## 섹터 기업 대조 범위

미국 기업 목록을 Yahoo 분류에 더해 iShares ITOT 공식 보유종목 섹터와
State Street 11개 Select Sector ETF 구성 공시에 정확한 티커로 대조한다.
미국 상장 주식만 사용하고 현금·파생상품·해외 거래소·이름 추정 ADR 매칭을 제외한다.
다른 섹터로 확인된 기업을 정정하고 공시에 있는 기업을 보완한다.
분류 근거·공시 기준일·미확인 여부와 전체 대조 범위를 표시한다.

이는 무료 공식 운용사 공시 대조이며 유료 GICS 전체 원장의 직접 검증과 다르다.
미확인 종목은 Yahoo 분류로 별도 표시한다. 시총 미수신 기업의 값은 만들지 않는다.
불완전한 시총 분모의 비중을 계산하지 않는다. 분류 공시는 별도 worker가 24시간마다
갱신하고 HTTP는 `market-classifications/sectors.json` 캐시만 읽는다.

## 수집과 탐색

섹터 기업 목록 → 기업 상세 → 관계도에서 다른 기업 상세로 이동한다.
검색·8개씩 페이지, 관계 종류 필터, 이전 화면·브라우저 뒤로 가기를 지원한다.
같은 섹터라는 이유로 직접 경쟁사로 표시하지 않는다. 관계선은 거래액·지분율이 아니다.

기본 관계도는 공급·고객·협력·경쟁 관계를 먼저 보여 준다. 소유·지분은 별도 필터로 본다.
각 기업에는 사업 역할·근거를 보존한다. 같은 대상·종류의 진술은 한 노드로 묶고
독립 근거는 각각 남긴다. 실제 발표 날짜가 최신인 근거를 같은 출처 등급에서 먼저 보여 준다.
열람 날짜를 발표 날짜로 사용하지 않는다. 작은 화면은 관계도 안에서 좌우로 스크롤한다.

관계 목록의 **업계 연결**은 현재 기업 → 선택한 기업 → 그 기업의 연결 기업을
8개씩 보여 준다. 공급·고객·협력·경쟁 필터, 페이지, 다시 읽기와 내부 기업 이동을
지원한다. 실제 저장된 첫 관계가 있어야 확장되며 같은 업종이라는 이유로 연결하지
않는다. 두 단계 경로가 첫 기업과 마지막 기업의 직접 거래를 뜻하지 않는다.
회사를 명시적으로 선택할 때만 캐시를 조회하며 화면을 옮기거나 소유자가 바뀐
이후의 늦은 응답은 버린다. 추가 출처는 현재 보이는 경로만 하단에 모은다.

HTTP GET은 캐시와 검증한 읽기 자료만 사용한다. POST는 로그인·CSRF·목록 확인·
60회/시간 제한 후 큐에 넣는다. 기업 수집에는 AI·증권사 키나 주문 기능이 없다.
큐 최대 200건, 프로세스 75초, 마지막 시도 후 5분의 중복 제한을 유지한다.
약 1분마다 섹터당 한 기업을 추가하고 정상 자료는 24시간, 실패는 1시간 뒤 갱신한다.
수동 요청을 먼저 처리하고 대기열 20칸을 남긴다. 섹터당 50개 후보씩 커서를 이어서 읽는다.
인터넷·공급자·목록 크기에 따라 전체 수집 시간이 달라진다.

SEC는 무료 공식 종목 목록의 정확한 티커로 CIK를 찾고 submissions에서 다시 확인한다.
이메일은 ignored `.env`의 `SEC_CONTACT_EMAIL`을 SEC User-Agent에만 사용한다.
Git·화면·로그에 값을 넣지 않고 company-data에만 전달한다.
submissions 최대 8MiB/50,000건, 공시 HTML 24MiB, 명세서 4MiB다.
고정 호스트·경로, redirect·환경 proxy 차단, 0.35초 SEC 요청 간격을 유지한다.
429는 Retry-After에 따라 해당 호스트를 1분~24시간 대기시키며 즉시 재시도하지 않는다.

공시 관계는 명시적인 회사 진술·경쟁 항목을 규칙으로 추출한다. 가정·부정·종료 문장과
익명 고객은 제외하고 알 수 없는 이름에 종목을 붙이지 않는다. 영어 증거 원문은 설명과
별도 필드에 보존한다. 모든 관계를 찾는 의미 분석이 아니므로 누락될 수 있다.
본문 80건·명세서 80건·기업 자료 100건·조회 400개 진술 제한을 유지한다.
실패 출처의 이전 자료를 보존하고 정상 갱신된 출처의 철회된 진술은 되살리지 않는다.

수집 버전 4는 SEC 공식 법인명/티커/CIK 목록의 정확한 이름 탐색으로 검토된
브랜드 별칭을 보완한다. 모호한 이름·미검토 복수 티커는 제외하며 이름 유사도로
추측하지 않는다. 문장 안의 구매·판매·협력·경쟁 절을 구분해 역할을 확인한다.
실제 관계의 근거는 이름 목록이 아니라 해당 발행사의 공시 문장이다.

제품 브랜드·해당 기업의 고객·공급사는 해당 기업 자체와 구분한다. 과거 버전의
자동 SEC 관계는 보존된 원문에서 같은 역할·상대방이 확인되는지 다시 검사한다.
확인되지 않는 기록만 공개 JSON/SQLite에서 제외하며 다른 발행사의 독립적인
근거와 직접 검토한 관계는 유지한다. 이 과정에는 외부 수집이나 AI 호출이 없다.

한국 OpenDART 수집기·실제 키는 아직 추가하지 않았다. `DART_API_KEY`는 예약 항목이다.
새 AI 호출은 건별 사용자 승인을 받아야 한다. 이 기능의 수집·기본 정리에 유료 호출이나
AI 평가 하네스·임베딩을 사용하지 않는다.

## 로컬 관계 저장소

`company-details/graph.sqlite3`은 기업·별칭·출처·자료·방향 있는 관계를 저장한다.
거래 DB와 분리되어 있으며 외부 DB·벡터 DB·LangGraph를 사용하지 않는다.
모델 검증 후 기존 JSON의 거부된 자료를 제거해 가져오며 공통 ID를 유지한다.

이름만 같은 기업을 합치지 않는다. 정확한 종목, 검증된 로컬 레지스트리, 기존 식별 별칭을
연결한다. 미확인 항목은 원문과 이름에 묶인 식별자로 저장한다. Lopez Foods·TRUMPF·
Carl Zeiss SMT 등은 별도 공식 자료 페이지가 있다. 비상장 기업에 임의 US 종목을 만들지 않는다.
상장 종목이 없는 페이지는 공식 관계·읽기 자료를 제공하고 자동 SEC 수집은 비활성화한다.

공급사↔고객사·자회사↔모회사 역방향에서도 원래 출처·진술 주체를 보존한다.
한 기업 갱신은 해당 기업의 진술만 바꾸고 다른 기업의 진술을 지우지 않는다.
SQLite 온라인 백업·무결성·외래키 검사를 유지하며 원본 WAL/SHM을 백업 파일로 복사하지 않는다.

## 모듈과 유지보수

- `company_research_catalog.py`: 무료 공식·공개 산업 문서의 한글 정리와 검증한 비상장 식별자.
- `company_industry_catalog.py`, `company_industry_reports.json`: 분야별 한국어 읽기 자료와 실제 연차 공시 근거.
- `company_research_notes.py`: 출처·사업·관계 읽기 자료의 공통 생성 함수.
- `company_catalog.py`: 기존 읽기 자료와 새 자료의 중복 없는 결합.
- `company_directory.py`: 차트/뉴스와 별개인 정확한 기업명 탐색·파일 변경 캐시.
- `company_provenance.py`: 백과 자료 제거와 긴 원문 분리.
- `company_relation_validation.py`: 과거 자동 SEC 관계의 역할·상대방 재검사.
- `company_feed.py`, `company_filings.py`: 제한된 수신·정확한 식별·공시 규칙 추출.
- `company_names.py`: 제한된 SEC 전체 법인명 인덱스와 정확한 이름 탐색.
- `company_revenue.py`: 동일 공시의 연간 매출 구성·단위·정확한 분모·포함 관계.
- `company_schemas.py`: 출처·길이·유한 수치·관계 종류 제한.
- `company_graph.py`, `company_entities.py`: 공통 ID·DB 이관·관계·역방향 탐색.
- `company_network.py`: 사업 관계의 두 단계 캐시 탐색·범위/페이지/근거 제한.
- `company_service.py`, `company_schedule.py`, `company_worker.py`, `company_retention.py`: 조회·큐·갱신·실패 보존.
- `static/company-research-view.js`: 한글 핵심·매출 표·원문·하단 출처의 순수 표시 함수.
- `static/company-page.js`, `company-relations.js`, `company.css`: 탐색·필터·페이지·SVG.
- `static/company-network.js`: 선택한 기업의 두 단계 업계 연결 표시·늦은 응답 차단.

새 사실은 해당 문서·기준일·범위와 함께 추가한다. 수집 출처는 고정 호스트·bounded reader를
통과해야 하며 사용자가 입력한 URL을 수집기에 그대로 전달하지 않는다.
CodeRabbit을 사용하지 않는다. 직접 코드·보안 검토와 기존 기능·프로세스 검사로 검증한다.
