# 개인 로컬 기업 백과

## 화면과 수집 흐름

섹터 상세 → 기업 목록(검색·8개씩 페이지) → 기업 상세 → 관계도에서 연결 기업 탐색.
제품·서비스와 관계도는 8개씩 표시한다. 관계도는 종류별로 필터링한다.
동일 섹터 기업 최대 80개도 별도로 탐색할 수 있다. 동일 분류를 직접 경쟁 관계로
해석하거나 관계선으로 지분율·거래량을 나타내지 않는다.

관계도의 기업과 목록의 기업 이름은 공통 ID 상세 페이지로 바로 이동한다.
‘관계·출처’ 버튼은 화면 이동 없이 원래 설명과 근거를 보여 준다. 이전 화면과
브라우저 뒤로 가기, 새로고침도 지원한다. 종목이 없는 기업은 시가총액이나 비중을
만들지 않으며, 식별자가 없는 원문 참조 항목도 내부 페이지에서 근거를 볼 수 있다.

기본 관계도는 소유·지분 관계를 제외하고 공급·고객·협력·경쟁 관계를 우선한다.
그 뒤에 모회사·자회사를 표시하며 각 묶음에서 기업·공시 원문을 먼저 배치한다.
소유·지분 관계와 전체 관계는 필터로 볼 수 있다. 카드에 사업 역할과 근거 수를
표시하고 공급·고객 및 모회사·자회사 방향에 화살표를 그린다. 이 순서는 거래 규모나
투자 중요도 점수가 아니다. 공개 백과의 과거 관계는 원자료에서 확인해야 한다.
작은 화면은 관계도 영역을 좌우로 스크롤해 글자를 읽을 수 있다.

애플은 [2025-08-06 공급망 발표](https://www.apple.com/newsroom/2025/08/apple-increases-us-commitment-to-600-billion-usd-announces-ambitious-program/)
에서 확인한 유리·레이저·칩 제조·패키징·희토류 자석·웨이퍼·장비 협력 기업과 역할을
보강했다. 투자·생산 확대 계획은 계획으로 표시하며 현재 완료된 공급량으로 취급하지
않는다. 새로 등록한 원문 관계는 이전 수집 캐시에도 중복 없이 합쳐 보여 준다.

HTTP GET은 로컬 캐시와 출처가 확인된 기본 설명만 읽는다. HTTP POST는
로그인·CSRF·종목 목록·60회/시간 제한을 확인한 뒤 공개 자료 수집을 큐에 넣는다.
`company-data`가 별도로 처리하며 AI·증권사 키·주문 기능을 사용하지 않는다.
자료는 24시간 뒤 갱신 대상이며, 마지막 시도 후 5분 동안 중복 수집을 제한한다.
큐는 최대 200건, 각 수집 프로세스는 75초로 제한한다.

## 출처와 제공 범위

| 출처 | 제공 항목 | 표시 구분 |
| --- | --- | --- |
| 기업 발표·사업보고서 | 사업·제품·관련 요인·확인된 공급/고객/협력/경쟁 관계 | 공시·기업 원문 |
| SEC submissions/companyfacts | 종목 일치 확인, 공시 링크, US GAAP·USD 연간 보고 수치 6종 | 공시·기업 원문 |
| Npay/WiseReport | 한국 기업 개요와 제공사 매출 구성 | 정보 제공사 |
| Wikidata | 종목 일치 후 제품·산업·자회사·모회사·소유 관계 | 공개 백과·원자료 확인 |
| Wikipedia | 출처·CC BY-SA 표기가 있는 기업 개요 | 공개 백과·원자료 확인 |
| Yahoo/Npay 섹터 기업 캐시 | 기업 목록, 시가총액, 수집 기업 내 비중 | 정보 제공사 |

제품 시장점유율은 조사 기간·시장 범위·원문이 확인된 자료만 등록한다.
시가총액 비중, 매출 구성, 제품 시장점유율은 서로 별개의 수치다.
SEC 재무 표는 최신 분기·예상치·통화 환산값을 만들지 않는다. 외국 기업의
IFRS/비USD 수치나 한국 공시 재무를 자동 표준화하는 기능은 현재 제공하지 않는다.
그 경우 공시·기업 원문과 제공사 사업 구성으로 확인한다. 모든 회사의 관계·점유율이
수신되거나 등록되었다는 보장은 없으며, 누락된 항목은 미등록으로 표시한다.

부분 실패하면 미수신 항목의 이전 자료를 유지하고 그 사실을 알린다. 프로세스
중단 시 기존 수집 시각을 보존한다. 원자료의 기준일과 현재 수집 시각은 다르다.
모든 출처는 항목별로 표시하며 하단 출처 모음은 접을 수 있다.

## 공통 기업 저장소 — 2026-10-01

`company-details/graph.sqlite3`에 기업, 별칭(종목/Wikidata/출처 내 식별), 출처,
기업·출처 연결, 기업 자료와 방향이 있는 관계를 저장한다. 거래 DB와 분리된
개인 로컬 공개 자료 저장소이며 외부 DB 서버·벡터 DB·LangGraph를 사용하지 않는다.
기존 JSON은 삭제하지 않고 검증해 가져온다. 이후 기업 조회는 DB 자료를 우선한다.
앱·기업 수집 프로세스가 시작할 때 이전 자료를 가져오며 반복 실행해도 공통 ID를 유지한다.

이름만 같은 기업은 합치지 않는다. 동일 종목 또는 Wikidata 식별자가 확인될 때
별칭을 연결하고 기존 ID는 새 ID로 안내한다. 식별자 없는 관계 항목은 원문과
이름에 묶인 항목으로 저장한다. 그 항목도 근거를 가진 페이지를 제공하지만 이름을
검색해 다른 기업의 자료를 붙이지 않는다.

`/api/company-entities/{공통ID}`는 로그인된 로컬 사용자만 조회할 수 있다.
공개 자료 추가 수집은 CSRF와 기존 회수 제한을 통과한 POST 큐로 요청한다.
종목이 없는 기업은 기존 관계에서 확인된 Wikidata ID를 그대로 조회한다.
공통 ID를 임의의 URL·파일 경로 또는 AI 요청으로 전달하지 않는다.

관계의 원래 주체·대상·유형·내용·출처·기준일·수집 시각을 보존한다. 대상 기업에서
같은 진술을 볼 때 공급사↔고객사, 자회사↔모회사 등 방향을 바꿔 표시하며 원래
어느 기업 자료의 관계인지 명시한다. 한 기업 수집은 그 기업이 제공한 관계만
교체하고 다른 기업이 제공한 관계를 삭제하지 않는다. 조회는 최대 400개 진술이다.
같은 대상·관계 종류의 여러 진술은 관계도에 하나로 묶고 ‘관계·출처’에 근거를
각각 표시한다. 원래 진술은 DB에 따로 보존하며 관계 종류가 다르면 별도로 표시한다.

기업 공개 자료 DB도 SQLite 온라인 백업으로 스냅샷을 만든다. WAL/SHM 파일을
그대로 압축하지 않으며 복원 전에 무결성과 외래키를 검사한다. 기존 백업 형식과
JSON 자료는 유지한다. RAG 질의응답은 별도의 향후 확장이며 이번 작업에 유료 AI
호출이나 임베딩을 추가하지 않는다.

## 모듈

- `company_catalog.py`: 확인한 사업 설명·관계·시장점유율과 원문/기준일.
- `company_feed.py`: 고정 호스트의 공개 자료 수신, 종목·CIK 검증, 파싱.
- `company_schemas.py`: 길이·유한 수치·출처 URL·관계 종류 제한.
- `company_service.py`: 캐시 조회, 큐 등록, 탐색 가능한 연결 기업.
- `company_worker.py`: 시간 제한, 실패 복구, 원자적 캐시 저장, 응답 기록.
- `company_graph.py`: SQLite 저장·공통 ID·별칭·관계·출처·역방향 조회.
- `company_entities.py`: 기존 자료 가져오기, 기업 ID별 상세 및 수집 큐.
- `static/company-page.js`, `company.css`: 표시·필터·페이지·접근 가능한 관계도.
- `static/company-relations.js`: 사업 관계 표시 순서·근거 선택·SVG 배치·방향.

새 기업의 확인된 설명은 catalog에 추가한다. 새 수집 출처는 feed의 고정 호스트
검증과 bounded reader를 통과해야 한다. 사용자가 입력한 URL을 수집 대상으로
그대로 전달하지 않는다. 출처 없는 추정 관계·점유율은 추가하지 않는다.

검증은 `tests/test_company_research.py`, `test_company_graph.py`,
`test_company_frontend.py`와 기존 개인 API·프로세스 검사를 사용한다.
AI 평가 하네스를 추가하거나 유료 AI 호출을 실행하지 않는다.
