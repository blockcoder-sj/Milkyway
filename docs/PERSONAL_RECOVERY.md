# 한 번으로 시작·복구하고 기존 계좌 이어가기

PC를 켠 뒤 **Milkyway 시작·복구**를 실행한다. Docker와 프로그램을 시작하고 기존
페이퍼 계좌를 재개한 뒤 브라우저를 연다. 화면의 **운용 상태 → 자동매매 복구·재개**는
선택한 계좌와 실행 프로세스를 함께 점검한다. 잔고·보유량·체결 기록을 초기화하지 않는다.

## 처음 준비

1. Docker Desktop과 Python 3.9 이상을 설치한다. Python은 이 시작·복구 실행기에
   필요하다. 기존 Docker 명령으로 수동 설치·운용하는 방법에는 추가되지 않는다.
2. 압축을 푼 밀키웨이 폴더에서 Mac은 `Milkyway-Start.command`, Windows는
   `Milkyway-Start.cmd`를 실행한다. 폴더를 이동했다면 새 위치의 파일을 사용한다.
3. 처음 설치일 때만 실행 이미지를 만든다. 이후에는 기존 컨테이너를 시작한다.
   기존 볼륨과 개인 백업을 복원하거나 삭제하지 않는다.
4. 전략 화면의 운용할 계좌를 선택한다. 처음이면 증권사 키·전략·페이퍼 계좌를
   먼저 준비한다. 시작 파일은 활성 계좌를 우선 선택하고, 없으면 재개 가능한
   최근 일시정지 계좌를 선택한다. 화면 버튼은 선택한 계좌만 재개한다.

이 PC에는 같은 실행 파일을 가리키는 바탕화면 바로가기를 만들 수 있다. 처음 실행의
Docker 안내와 OS 권한 안내는 본인이 확인한다. Python이 없다면 공식 python.org의
운영체제별 설치 파일을 사용한다. Windows에서는 Python Launcher 또는 python 명령을
사용할 수 있어야 한다. 실제 Windows PC 검증은 별도로 필요하다.

## 화면의 상태 읽기

| 상태 | 의미와 다음 동작 |
| --- | --- |
| 자동매매 정상 | 프로세스·계좌·당일 자료·필요 종목 최신 시세가 준비됐다. 전략 조건에 따라 매매하거나 보유한다. |
| 미국 정규장 대기 | 프로세스와 계좌가 켜져 있다. 개장 후 자료와 시세가 준비되면 자동 운용한다. |
| 일봉·분할·배당 확인 대기 | 자료를 자동 갱신한다. 확인 전에는 체결하지 않는다. |
| 인터넷·증권사 연결 끊김 | 새 시세가 없어 대기한다. 인터넷이 돌아오면 활성 계좌는 자동으로 다시 시도한다. |
| 프로그램 응답 확인 필요 | 마지막 화면을 정상 상태로 믿지 않는다. 복구·재개로 프로세스를 확인한다. |
| 허용 IP 확인 필요 | 학교·집·VPN 변경으로 IP가 달라졌을 수 있다. 토스 WTS의 허용 IP를 직접 수정한다. |
| 지정 거래일 운용 종료 | 하루 전용 계좌의 일정이 끝났다. 기록은 보존하며 자동으로 다음 날 계좌를 만들지 않는다. |
| 계좌 검토 필요 | 기업행사·시세·전략 경고를 확인한다. 복구 버튼으로 경고를 우회하지 않는다. |

프로그램 응답과 자동매매 가능 상태는 별개다. 마지막 상태 확인 시각, 프로세스 응답,
증권사 시세 수신, 엔진 판단, 실제 가상 체결 시각을 함께 볼 수 있다. 연결 중에는
5초마다 상태를 확인한다. 장외·후보 없음·기존 보유 유지 상황에서는 새 체결이 없을 수 있다.

복구할 때는 개장 전에도 본인 API로 실제 연결을 점검한다. 최근 API 연결 점검의
성공 시각을 확인할 수 있다. 점검 가격은 체결용 시세 원장에 넣지 않는다.

## 외출·인터넷 끊김·PC 종료 뒤

- 인터넷만 끊겼다면 기존 활성 계좌가 자동 재시도한다. 집에 돌아온 뒤 최신 상태가
  갱신되는지 본다. 시세 공급자 오류 뒤에는 약 1분의 재시도 대기가 있을 수 있다.
- 프로그램이나 프로세스가 멈췄다면 화면의 복구·재개를 누른다. 화면을 닫았거나
  PC를 껐다 켰다면 바탕화면 또는 밀키웨이 폴더의 시작·복구 파일을 실행한다.
- PC와 Docker, 인터넷이 꺼진 동안에는 로컬 자동매매가 실행되지 않는다. 복귀 뒤
  새 시세로 이어가며, 중단 시간의 가격이나 손절 체결을 소급해서 만들지 않는다.
- 장중에는 전원·인터넷을 유지하고 절전·덮개 닫기를 피한다. 종료는 프로그램의
  서비스 중지 명령으로 처리한다. 기록을 지우는 초기화나 볼륨 삭제를 사용하지 않는다.

일주일을 같은 계좌로 운용하려면 계좌 생성의 **하루만 운용할 미국 거래일**을 비워
계속 운용 계좌로 만든다. 하루 계좌가 끝난 경우 새 계좌는 별도로 만들고 이전 결과와
구분한다. 복구는 기존 계좌 재개이며 새 가상자금 지급이나 포지션 청산이 아니다.

## 실행기 동작과 보관

시작·복구 실행기는 본인 PC의 127.0.0.1:19480에서만 동작한다. 웹 앱의 인증된
개인 모드와 비공개 연결 토큰으로 통신한다. 다른 Origin·Host·명령은 거절한다.
명령은 app·paper-worker·personal-data·backtest-worker·market-data·backup의 시작과
필요한 재시작으로 제한한다. 웹 앱에 Docker 소켓을 연결하지 않는다.

시작·복구 실행기를 끝내려면 `python3 deploy/local_control.py stop`을 사용한다.
Windows는 `py -3 deploy/local_control.py stop`을 사용할 수 있다. 이는 작은 실행기만
끝내며 페이퍼 운용 프로세스는 그대로 둔다. 서비스 전체 중지는 기존 Compose stop을
사용한다. 다른 프로젝트와 Docker 엔진 전체를 함께 종료하지 않는다.

runtime/local-control과 개인 Docker 볼륨의 연결 파일은 본인만 보관한다. API 키·.env·
개인 백업 ZIP과 마찬가지로 공유하거나 GitHub에 올리지 않는다. 이 기능은 개인 PC용이며
공개 서버나 여러 회원의 키를 수집하는 배포에 사용하지 않는다.
