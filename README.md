# Milkyway

개인 PC에서 미국 주식 전략을 만들고, 본인 증권사 시세로 가상 매매 기록을 쌓는 도구입니다.
**증권사에 매매 주문을 보내지 않습니다.** 주가는 한국투자증권(KIS)·토스증권 API에서
조회하고 체결·현금·보유 수량은 이 PC의 로컬 원장에 저장합니다.

## GitHub에서 받아 실행

Python 3.14를 설치하고 GitHub 기본 `main` 브랜치에서 **Code → Download ZIP**으로
소스를 받습니다. 압축을 풀고 VS Code의 **파일 → 폴더 열기**로 그 폴더를 엽니다.
`run_milkyway.py`가 보이면 **터미널 → 새 터미널**에서 본인 명령 하나를 실행합니다.

```powershell
# Windows
py -3.14 run_milkyway.py
```

```bash
# Mac
python3.14 run_milkyway.py
```

첫 실행은 전용 `.venv`와 해시로 고정한 구성요소를 설치합니다. 이후에는 같은 환경을
재사용합니다. 기존 Python 3.12·3.13도 지원하며 명령의 버전 부분을 맞춥니다.
웹과 운용·백테스트·일봉·시장 시세·시장 상세·백업 프로세스를 함께 시작하고 브라우저를 엽니다.
실제 접속 주소는 터미널에 표시됩니다. AI 키·Git 설치·Docker가 필요하지 않습니다.

프로필에서 본인 토스 API를 연결하고 전략 연구 대화에서 전략을 만든 뒤 계속 운용 페이퍼 계좌를 만듭니다.
장중에는 VS Code 터미널·PC·인터넷을 유지하고 절전을 막습니다. 종료할 때는 실행 중인
터미널에서 **Ctrl+C**를 누르고 **종료 완료**를 확인합니다. 다음 날 같은 폴더에서 같은
명령을 실행합니다. 기록은 `runtime/`, 백업은 `backups/`, 실행 로그는 `logs/`에 남습니다.
개인 키와 `runtime`·`backups`는 제출하거나 GitHub에 올리지 않습니다.

추가 백업은 실행 명령 끝에 `backup`, 진단은 `doctor`를 붙입니다.
이 구성은 본인 PC의 내부 페이퍼 체결 전용이며 실제 증권사 주문을 보내지 않습니다.
Windows는 파일 잠금·사용자별 폴더 권한·자식 프로세스 정리를 별도로 적용합니다.
Windows의 처리 시간 초과는 해당 프로세스를 종료하고 감독 프로세스가 다시 시작합니다.
Python 3.15와 Windows ARM64는 이번 확인 범위에 포함하지 않습니다.

## 이미 ZIP으로 설치했다면: 한 줄 업데이트

모든 설치·업데이트는 같은 `main` 코드를 사용합니다. 기존에 교육용 ZIP으로 설치했어도 이 명령으로 같은 프로그램으로 업데이트됩니다.

밀키웨이 실행 창에서 **Ctrl+C**를 누르고 `종료 완료`를 확인합니다.
VS Code에서 **기존 밀키웨이 폴더**를 열고 아래 명령 하나를 실행합니다.
Git 설치나 ZIP 재다운로드·폴더 교체가 필요하지 않습니다.

```powershell
# Windows: 이전 버전에도 동작하는 업데이트 명령
py -3.14 -c "import urllib.request;exec(compile(urllib.request.urlopen('https://raw.githubusercontent.com/blockcoder-sj/Milkyway/main/update_milkyway.py',timeout=30).read(262144),'update_milkyway.py','exec'))"
```

```bash
# Mac: 이전 버전에도 동작하는 업데이트 명령
python3.14 -c "import urllib.request;exec(compile(urllib.request.urlopen('https://raw.githubusercontent.com/blockcoder-sj/Milkyway/main/update_milkyway.py',timeout=30).read(262144),'update_milkyway.py','exec'))"
```

`업데이트 완료`가 표시되면 평소의 `py -3.14 run_milkyway.py` 또는
`python3.14 run_milkyway.py`로 다시 실행합니다. 업데이트는 자동으로 매매를 재개하지 않습니다.
이번 업데이트 이후에는 실행 명령 끝에 `update`를 붙여도 됩니다.

최신 실습 브랜치의 코드를 받고 `runtime`, `backups`, `logs`, `.venv`, `.env`를 보존합니다.
키를 읽거나 다시 입력하지 않습니다. 실행 중이면 업데이트를 차단하고, 파일 교체 오류는
교체 전 코드로 복원합니다. 개인 폴더를 지우거나 새 폴더로 옮기지 않습니다.

### 2026-11-06: 토스 인증 충돌·수집 오류 안내 수정

토스는 Client ID당 유효한 액세스 토큰이 하나이며 새 토큰을 발급하면 이전 토큰이
무효화됩니다. 같은 PC의 전체 종목 이력 수집·페이퍼 운용·화면 시세가 각각 토큰을
발급하던 경로를 수정해, 개인 PC 모드에서 암호화한 토큰 하나를 프로세스 간 공유합니다.
이전 토큰으로 진행 중이던 요청도 다른 프로세스가 갱신한 토큰을 받아 한 번 재시도합니다.

기존의 모든 `403`을 IP 차단으로 표시하던 안내도 수정했습니다. 실제 허용 IP 불일치,
`edge-blocked`, 접근 권한 거부, 인증 실패를 구분해 프로필과 수집 상태에 표시합니다.
전체 종목 수집 중 인증·권한 거부는 일시 대기 후 재시도하며 종목별 이력 부족은 계속
Yahoo로 보완합니다. 키 재발급 횟수 자체를 IP 차단 원인으로 판정하지 않습니다.

위 업데이트 명령으로 갱신한 뒤 다시 실행합니다. 기존 전략·계좌를 다시 만들 필요는
없습니다. 키를 재발급했다면 프로필에 최신 Client ID와 Secret을 함께 저장하세요.
서로 다른 PC·폴더·외부 프로그램이 같은 Client ID의 토큰을 따로 발급하면 여전히
충돌할 수 있습니다. 실제 허용 IP 오류는 API를 실행하는 PC의 공인 IP를 WTS에 등록해야 합니다.
최초 전체 이력 준비가 끝나고 장중 시세·전략 조건이 충족되어야 매매를 시작합니다.

단일 토큰 제한을 적용한 로컬 HTTP 서버와 세 자식 프로세스로 재현했고 전체 848개
테스트를 통과했습니다. 실제 이용자의 토스 키·설치 PC에서 성공을 확인한 결과는 아닙니다.
[토스 공식 FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md),
검증 기록: `docs/TOSS_AUTH_REVIEW_20261106.json`.

### 2026-11-05: 전략·페이퍼 계좌 삭제

별도의 `직접 규칙 입력` 화면을 제거했습니다. 전략은 연구 대화에서 만들고, 저장한 버전의
비중·주기·손절 등은 기존 운용 설정에서 조정합니다. 미국 전체 자동 선정에는 티커를
미리 지정할 필요가 없습니다. 지원 가능한 규칙은 가격·거래량 기반 6종 신호 범위입니다.

`내 페이퍼 계좌`의 **계좌 삭제**는 확인 후 해당 계좌의 보유·체결·자산·거래일 기록을
함께 영구 삭제합니다. 실제 증권사 계좌나 주문에는 영향을 주지 않습니다.
`내 전략`의 **전략 삭제**는 전략과 연결된 백테스트 기록을 삭제합니다. 연결된 페이퍼 계좌가
있으면 먼저 삭제해야 하며, 백테스트나 승인 대기·실행 중인 AI 요청이 있으면 안내에 따라
완료·취소한 뒤 다시 시도합니다. 다른 계좌와 연구 대화는 유지합니다.

삭제한 버전이 포함된 비교 실험은 무효로 표시하며 새 비교를 실행해야 합니다.
남은 버전의 번호는 유지하고, 삭제한 계좌의 이전 요청을 다시 보내도 계좌를 재생성하지 않습니다.
개인 PC 모드에서 본인 자료만 삭제할 수 있습니다. 이 업데이트가 기존 자료를 자동 삭제하지는 않습니다.

### 2026-11-05: 미국 상장주식 전체에서 자동 선정·배분

새 연구 대화의 전략은 **미국 상장주식 전체**를 기본 범위로 사용합니다. 전략 생성 때 티커를
입력할 필요가 없습니다. 공식 상장 목록을 매일 갱신하고 보통주·ADR·REIT를
탐색합니다. ETF·우선주·워런트·유닛·OTC는 제외합니다. 고정된 20개·500개 목록으로
탐색 범위를 대신하지 않습니다. 저장한 전략의 선정 범위는 운용 설정에서 확인할 수 있습니다.

운용 시 가격 신호와 최소 주가 필터는 **최신 토스 시세 + 완료된 과거 일봉**으로
평가합니다. 거래량 신호·평균 거래량은 완료 일봉을 사용합니다. 전체 탐색의 수정 일봉은
토스를 우선하고 부족하면 Yahoo로 보완합니다. 모멘텀·평균회귀·저변동성·이동평균·
거래량 모멘텀·RSI의 지원 규칙을 사용하며, 뉴스·재무제표를 읽는 전략까지 구현한 것은 아닙니다.

전체 목록의 조회를 마친 뒤 순위를 계산합니다. 제공되지 않는 이력, 누락·지연·미래 시세는
제외하고 계좌에 전체·평가 가능·제외 건수와 선정 시각·목표 비중을 표시합니다.
탐색 결과와 선정 종목 시세는 최대 180초 이내여야 하며, 실제 체결에는 별도로 다시 받은
최신 증권사 시세를 사용합니다. 종목당 목표는 `min(전체 투자 비중 / 선정 종목 수, 종목당 상한)`이며
남는 금액은 현금입니다. 매수·매도 비용을 반영하고 새 전략은 유지 종목 비중도 재조정합니다.

전체 탐색은 체결·손절 프로세스와 분리되어 있습니다. 신규 리밸런싱은 정규장 개장 5분 후부터
마감 15분 전까지, 손절은 정규장 안에서 처리합니다. 분할·배당 확인은 기존 Yahoo 검증을
유지하므로 Yahoo가 모든 경우에 선택적인 것은 아닙니다. 필요한 기업행사 확인이나
최신 시세가 없으면 거래를 보류하고 자동 재시도합니다. 합성 가격으로 대체하지 않습니다.

처음에는 전체 종목의 이력 준비 시간이 필요합니다. 운용 상태에 진행 건수를 표시합니다.
앱 실행 창과 PC를 켜 두면 준비·재시도를 계속합니다. 거래가 없는 원인을 확인할 때는
증권사 인증, 전체 탐색 진행률, 계좌별 실행 상태를 함께 확인하세요.

기존 전략은 저장된 지정 종목을 유지합니다. **전략 연구 → 직접 조정 → 선정 범위에서
미국 상장주식 전체 → 새 버전 저장**으로 AI 추가 호출 없이 전환할 수 있습니다.
그 버전으로 새 페이퍼 계좌를 만들면 적용됩니다. 이전 계좌·체결 기록을 덮어쓰지 않습니다.
새 계좌를 만들 때 토스 연결이 필요합니다. 체결용 목표·보유 시세 용량은 활성 계좌 합계
200개이며, 전체 시장을 탐색하는 종목 수와 별개입니다.

자동 탐색의 과거 이력은 최근 320거래일입니다. 백테스트 시작 전 관찰 기간이 부족하면
시작일을 뒤로 조정해야 합니다. 현재 상장 목록에서 역사적 시점마다 다시 선정하는 탐색 검증이며
상장폐지 종목을 복원한 PIT 성과는 아닙니다. 역사적 검증은 전일 신호·다음 시가를 사용하므로
장중 최신 시세를 반영하는 페이퍼 운용과 실행 시점이 다릅니다. 비교 실험의 데이터는 고정해
보존하고, 복원 시 일시적 탐색 시세는 새로 수신합니다.

### 2026-11-05: 정규장이 열렸는데 첫 체결이 대기하는 경우

Yahoo가 당일 일봉의 가격을 비워 반환하면 분할·배당 확인도 완료되지 않아
첫 매수가 계속 대기하던 경로를 수정했습니다. 일봉으로 확인하지 못한 종목은
정규장 5분봉의 분할·배당 데이터로 보완합니다. 직접 지정 전략의 신호는 전날까지의 일봉으로,
체결은 본인 증권사 시세로 계산합니다. 전체 미국 자동 전략의 신호는 위 설명처럼 장중 가격도 반영합니다. 위 방법으로 기존 폴더를 업데이트하고
다시 실행하면 수집 프로세스가 자동으로 재시도합니다.

연속 운용에서는 장 마감 뒤 체결을 막고, 응답이 멈춘 작업을 재시작하며,
프로세스 재시작 시 로그 파일 핸들이 누적되지 않도록 수정했습니다.
가속 시간의 7거래일·1,000회 반복과 전체 811개 검사를 통과했습니다.
실제 토스 연결로 7일 연속 운용을 확인한 결과는 아닙니다.

지정 거래일이 이미 마감된 페이퍼 계좌는 종료 상태를 유지합니다.
다음 거래일을 운용하려면 그 날짜의 새 세션이나 계속 운용 계좌를 만듭니다.

## AI 가설 연구

전략 화면에서 가설 대화 → 버전 저장 → 개발·검증 비교 → 개선 → 페이퍼 운용을
진행할 수 있습니다. 기본 모델은 `gpt-5.4-mini`, 추론은 `none`입니다.
`.env`에 본인 키를 넣고 **요청마다 1회 호출을 승인**합니다. 자동매매에는 AI 호출이 없습니다.
Docker 없이 Python 실행에서도 `run_milkyway.py`와 같은 폴더의 `.env`를 읽습니다.
`.env.example`에 이미 키를 넣었다면 그 파일을 복사해 이름을 `.env`로 바꾸고 재실행하면 됩니다.
이번 업데이트부터는 `.env`가 없을 때 `.env.example`의 AI 설정도 그대로 읽습니다.
기존 `.env`가 있으면 해당 파일을 우선하며, 두 파일과 개인 기록을 업데이트로 덮어쓰지 않습니다.
[키 설정·전체 흐름·지원 범위](docs/AI_RESEARCH_GUIDE.md)

## 학회원 개인용 빠른 시작

Docker Desktop(Windows/macOS) 또는 Docker Engine + Compose(Linux)를 실행하고,
저장소를 내려받습니다. Git 대신 GitHub의 **Code → Download ZIP**도 가능합니다.
비공개 저장소라면 먼저 저장소 접근 권한이 필요합니다.

```bash
git clone --depth 1 --branch main https://github.com/blockcoder-sj/Milkyway.git
cd Milkyway
docker compose -f compose.personal.yaml up -d --build
```

1. <http://localhost:8080>을 열면 가입·로그인 없이 전략 화면으로 들어갑니다. 기존 계정이 하나 있으면 기록을 그대로 사용하고, 새 설치에서는 로컬 계정을 자동 생성합니다.
2. 프로필에서 본인 KIS App Key/Secret 또는 토스 Client ID/Secret을 연결합니다. AI 키는 필요 없습니다.
3. AI 연구 대화에서 투자 가설·선정 기준·보유 수·주기를 설명하고 전략을 저장합니다. 일반 미국 주식 전략은 전체 시장 자동 선별을 기본으로 합니다. AI로 새 전략을 작성할 때는 본인 AI 키와 호출 승인이 필요합니다.
4. 미국 전체 일봉 분석이 끝나면 탐색용 백테스트를 실행하고 페이퍼 계좌를 만듭니다. 운용 기간의 기본값은 7일이며, 종료 시 추가 체결을 자동 중지합니다.
5. 미국 정규장에 PC와 Docker를 켜 둡니다. 화면의 운영 상태·계좌별 대기 사유·최근 시세를 확인합니다. 시장 탭의 공개 참고 시세는 페이퍼 체결에 사용하지 않습니다.

PC를 껐다 켰거나 실행이 멈췄다면 Mac의 `Milkyway-Start.command`, Windows의
`Milkyway-Start.cmd`를 실행합니다. 이 실행기에는 Python 3.9 이상이 필요합니다.
열린 화면에서는 **운용 상태 → 자동매매 복구·재개** 한 번으로 프로세스와 선택 계좌를
점검하고 기존 기록을 이어갑니다. [상태 표시·인터넷 끊김·시작과 복구](docs/PERSONAL_RECOVERY.md)

[처음부터 따라 하는 사용설명서·문제 해결](docs/Milkyway_초보자_사용설명서.md) ·
[검증 범위와 남은 실환경 확인](docs/Milkyway_검수보고서.md)

- 토스 연결은 거래 가능한 미국 보통주·ADR·REIT 전체를 매일 분석합니다. 종목 수는 공급자 목록에 따라 바뀝니다. ETF·우선주·워런트는 제외합니다. 티커를 미리 고를 필요가 없습니다.
- 전체 분석과 동시 가격 감시는 별도입니다. 보유·선정 종목만 감시하며 토스는 200개, KIS는 20개 한도입니다. 직접 종목을 지정한 기존 전략은 유지되며 저장된 선택 종목의 합계는 최대 100개입니다.
- 전체 시장 분석 일봉은 토스에서, 선정·보유 종목의 기업행사 확인 자료는 Yahoo에서 갱신합니다. 실시간성 가격은 **본인 증권사 REST 시세 조회**를 사용합니다.
  15초 간격으로 조회를 시도하며 KIS 모의 환경은 5종목씩 순환합니다. 전체 20종목은 통상
  약 1~2분에 갱신됩니다. 거래소 원시 tick 스트림이 아니며 시세 지연 여부는 계정 권한에 따릅니다.
- 개인 선택 종목의 백테스트는 탐색용입니다. 과거 전체 상장 종목을 인증한 무편향 성과로 표시하지 않습니다.
- 기록은 재시작 후 유지됩니다. 계좌의 `삭제`는 해당 잔고·체결·자산 기록을 삭제합니다. 전략을 삭제하려면 연결된 계좌를 먼저 삭제해야 합니다. 삭제 전에 CSV로 내보낼 수 있습니다. 직접 규칙 입력 폼은 제거했습니다.
- 6시간마다 별도 Docker 볼륨에 백업합니다. 다른 디스크에도 복사해야 PC/디스크 고장에 대비할 수 있습니다.

```bash
# 정상 중지: 기록 유지
docker compose -f compose.personal.yaml stop
# 재개
docker compose -f compose.personal.yaml up -d
# 진단
docker compose -f compose.personal.yaml exec app python -m cloud_app.local_ops doctor
# 즉시 백업 + PC로 복사
docker compose -f compose.personal.yaml exec backup python -m cloud_app.local_ops backup
docker compose -f compose.personal.yaml cp backup:/app/backups ./backups
```

백업에는 암호화된 자격증명과 복호화 키가 함께 포함되므로 개인 파일로 보관합니다.
복원·포트 충돌·비밀번호 분실·API 연결 실패는 사용설명서의 절차를 따릅니다.
**Docker 볼륨을 지우거나 `down -v`를 실행하면 기록이 삭제됩니다.**
브라우저를 닫아도 실행은 계속되지만 PC 절전·종료·Docker 중지는 거래를 멈춥니다.
재연결 후 정상 처리하며, 꺼져 있던 시간의 실시간 체결을 소급하여 만들지는 않습니다.

개인용 구성은 `127.0.0.1`에만 열립니다. 이 PC를 사용하는 사람은 비밀번호 없이 기록과 설정에 접근할 수 있습니다. 공유 컴퓨터·포트 포워딩·공개 서버용 구성이 아닙니다.
중앙 서버 배포 자체가 불가능한 것은 아니지만, 사용자 인증·키 격리·운영 보안이 필요한 별도 설계입니다.
아래 기존 클라우드 구성의 보안 검증과 운영 gate는 그대로 유지합니다.

## 기존 클라우드 구성

Milkyway Quant Trading Lab은 퀀트 동아리 회원이 자연어 전략을 안전한 전략 규격으로
변환하고, 공통 체결 엔진으로 백테스트한 뒤 페이퍼 계좌에서 운용할 수 있는 웹 플랫폼이다.

## 주요 기능

- 수신자 이메일 결합 1회 초대 기반 계정과 사용자별 전략·백테스트·페이퍼 계좌
- 미국·한국 시장 지표, 섹터 흐름과 경제 뉴스 화면
- 운영자 소유 OpenAI·Anthropic 키 또는 서버 공용 로컬 AI를 이용한 전략 코드 생성
- 각 회원의 증권사 키로 수집하는 개인 페이퍼 트레이딩 시세
- 미래참조를 제한하는 전략 DSL과 공통 백테스트·페이퍼 체결 규칙
- Docker, PostgreSQL, Caddy, worker, scheduler와 백업 구성

회원은 AI 키를 입력하지 않고 동아리 공용 AI를 사용한다. 증권사 키는 별도 broker VM의
`/credentials` 페이지에서 본인 계정으로 등록·교체·삭제한다. 공개 앱을 거치지 않은 키를
broker가 검증하고 OCI KMS 암호문으로 저장하며, 앱·worker는 원문 키나 암호문을 받지 않는다.

독립 발급된 불투명 회원 세션과 PostgreSQL RLS가 회원 데이터를 분리한다. 공용 AI에는
회원·프롬프트에 결합된 일회용 허가가, worker에는 broker가 선택한 계좌·종목에만 유효한
작업 권한이 필요하다. 개인 키로 받은 시세는 해당 회원의 계좌에만 사용하며 공용 시세로
대체하지 않는다. TradingView Widget은 화면 표시용이며 페이퍼 엔진 입력으로 추출하지 않는다.
REST 현재가 polling을 사용하며 WebSocket 체결 스트림이나 실거래 주문은 지원하지 않는다.

**공개 서버 배포와 그 서버에 회원 키를 모으는 운영은 현재 NO-GO다.** 로컬 테스트는 실제 두 VM의 KMS allow/deny,
Vault secret release와 OCI Audit 검증을 대신하지 않는다. 현재 증거와 남은 gate는
[SECURITY_REMEDIATION_STATUS.md](SECURITY_REMEDIATION_STATUS.md)를 확인한다.

공용 AI는 `SHARED_AI_PROVIDER`, `SHARED_AI_MODEL`과 `OCI_SHARED_AI_SECRET_ID`로 고정한다.
운영 환경에서 원격 OpenAI/Anthropic 키는 broker VM의 instance principal이 OCI Vault에서
조회한다. 평문 키 환경변수나 키 파일은 시작 전에 거부한다. `local`을 선택하면 운영자가 관리하는 공용 모델 서버를
사용한다. 기본 배포 구성은
llama.cpp의 OpenAI 호환 API와 `Qwen2.5-Coder-7B-Instruct-GGUF` Q4_K_M 모델이다. 모델
엔드포인트는 서버 환경변수로만 정하며 사용자가 임의 URL을 입력할 수 없다. 활성화하려면
브로커 VM의 `deploy/credential-broker.env`에서 `COMPOSE_PROFILES=local-ai`,
`LOCAL_AI_ENABLED=true`와 임의의 키 파일을 가리키는
`LOCAL_AI_API_KEY_PATH`를 설정한 뒤 다음과 같이 로컬 AI 프로필을 함께 실행한다. 첫 실행에서는
약 5GB 모델 다운로드와 로딩 때문에 수 분이 걸릴 수 있다.

기본 `LOCAL_AI_MODEL_URL`은 검증한 Hugging Face revision에 고정되어 새 서버에서도 같은
GGUF를 받는다. 운영자가 모델을 바꿀 때는 모델 ID와 revision 고정 URL을 함께 변경한다.

```bash
docker compose --env-file deploy/credential-broker.env \
  -f compose.credential-broker.yaml --profile local-ai up -d --build
```

로컬 AI는 별도 API 호출료가 없지만 CPU/RAM을 사용한다. 7B Q4 모델 기준으로 앱·데이터베이스와
함께 운영하려면 16GB보다 24GB RAM 구성이 안전하며, 동시 생성은 기본 2개 슬롯으로 제한한다.

## 실행

production은 공개 앱 VM과 broker VM을 분리하고 PostgreSQL TLS, 역할별 DB 계정,
독립 인증 발급, KMS/Vault 및 검토한 데이터 세대를 함께 설정한다. 실제 배포는
[CLOUD_DEPLOYMENT.md](CLOUD_DEPLOYMENT.md)의 **DB → broker → 앱·worker** 순서를 따른다.
기존 env·DB·runtime·Docker 볼륨을 덮어쓰거나 초기화하지 않는다.

### API 없이 화면·백테스트를 살펴보는 합성 데이터 모드

```bash
docker compose -f compose.local.yaml up -d --build
```

이 별도 모드는 ALPHA/BETA/GAMMA 합성 일봉을 사용하는 탐색용 백테스트 연습이다.
실제 시세 수신과 실시간 페이퍼 운용은 앞의 개인용 구성으로 실행한다.
합성 데이터는 PIT 인증 데이터가 아니며 실제 투자 성과가 아니다.

실제 인증된 데이터셋으로 연구하려면 별도 `data_cache/`를 준비하고 아래의 개발 실행 경로를
사용한다. `data_cache/`, `runtime/`, `.env`와 개인 키 파일은 Git에 포함하지 않는다.

```bash
docker build -t milkyway:local .
docker run --rm -p 127.0.0.1:8080:8000 \
  -e APP_ENV=development \
  -e DATASET_DIR=/app/data_cache/backtest_datasets/2026_equities_pit_20260824 \
  -v "$PWD/data_cache:/app/data_cache:ro" \
  milkyway:local uvicorn cloud_app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

## 테스트

```bash
docker build -t milkyway:test .
```

```bash
python3 tests/run_postgres_checks.py --image milkyway:test
```

### 코드 배치와 정리 기준

- `cloud_app/`: 서버 API, 데이터 수집, 전략 실행과 페이퍼 원장. 계좌·시세 처리는 화면 코드와 분리한다.
- `cloud_app/static/format.js`: 숫자·금액·시간·HTML 이스케이프의 공통 표시 함수. 화면 모듈은 이를 재사용한다.
- `cloud_app/static/research/`: 전략 대화의 API·화면·설정 책임을 분리한 모듈.
- `tests/`: 합성 시세와 장애 상황을 포함한 회귀 검사. 테스트 자료는 실제 거래 시세가 아니다.
- `deploy/`, `compose*.yaml`: 실행·백업·운영 도구. 사용하는 실행 방식이 다르므로 다른 구성 파일을 미사용 파일로 간주하지 않는다.
- `runtime/`, `backups/`: Git 제외 개인 데이터·검증 기록·보관 자료. 프로그램 정리 시 삭제하지 않는다.

기본 실행과 명시적 데모 실행을 구분한다. `local_demo.py`와 테스트 fixture는 검증에 사용하므로 유지한다.
사용하지 않는 파일은 코드·HTML·CSS·실행 구성의 참조를 확인한 뒤 삭제한다. 화면 공통 함수는 각 페이지에 복사하지 않는다.
